# 0.12.0 语音交互

更新：2026-11-03。继续使用 Go 标准库、原生 JavaScript 和 Kotlin 平台 API，无新增第三方依赖。

## 使用

Android 输入框旁新增“语音输入”：打开手机的系统识别界面，识别结果回到可编辑草稿，点击发送后才进入已有聊天队列。取消不发送、不创建会话、不调用聊天模型。无可用系统识别服务时提示使用键盘语音输入；旧 APK 提示更新。网页仍使用文字/键盘输入，不启用浏览器的实验性语音识别。

完整回答下方新增“朗读”。点击才调用服务器合成，显示播放控件和停止入口；同一段最近音频可在本页面重听，最多保留一份内存音频。无自动朗读，不由 LLM 工具或关怀调度触发。播放控件受设备策略限制时，点击控件播放即可。

发送新消息、切换会话、重置、退出登录或进入后台会停止播放/未完成的合成请求；切换会话、重置和退出会清理当前片段。录音不会存到聊天服务；系统识别可能由手机厂商/所选识别服务联网处理，不能承诺离线识别。手机继续不持有模型 API Key。

## 服务端配置

在原服务环境文件中显式设置：

```sh
POCKET_TTS_MODEL=ecnu-tts
POCKET_TTS_VOICE=xiayu
```

复用 `POCKET_BASE_URL` 与服务器的 `POCKET_API_KEY`，聊天模型仍为 `ecnu-max`；不设置 `POCKET_TTS_MODEL` 或处于演示模式时关闭朗读。仅开放鉴权后的 `POST /api/voice/speech`，请求 JSON 为 `{"input":"要朗读的文字"}`，响应 MP3；客户端不能指定供应商地址、密钥或模型。

每次最多 1200 个 Unicode 字符、一个并发、两次生成至少间隔 10 秒，30 秒超时，音频最多 2 MiB。错误不转发上游原文、密钥或文本，不自动重试或更换供应商。不保存音频文件/缓存，认证 API 与音频不进入 Service Worker 缓存；客户端只暂存一段内存音频。长回答禁用朗读入口并说明上限，不自动截断或拆成多个收费请求。

取消是停止等待/播放，供应商已经收到的合成可能仍计费；页面刷新或选择别的回答后重新合成会重新使用额度。该节流是当前服务进程内保护，不是持久化日预算。朗读与关怀预算相互独立。

## 能力核对与最小验证

官方文档：[ECNU 语音合成](https://developer.ecnu.edu.cn/vitepress/llm/api/audio.html)、[Android RecognizerIntent](https://developer.android.com/reference/android/speech/RecognizerIntent)。ECNU 当前公开接口列出了语音合成，本版未假设其提供可用的语音转写接口，输入先使用 Android 已有系统服务。不是实时通话或服务器 ASR。

服务器仅做一次虚构短文本合成：HTTP 200、audio/mpeg、8588 字节，端到端约 0.55 秒。此单次耗时仅作接通证据，不代表持续延迟保证；不虚构每字价格。后续界面验证复用此合成素材，不重复消耗模型额度。

新增一条离线 Go 集成流程，覆盖鉴权、输入上限、二次生成限流、并发、取消和错误脱敏；另运行已有事件/关怀流程，均通过。Android 离线构建成功。隔离 API35 模拟器验证实际 MP3 播放、同片段重听不重新合成、切换会话清理、真实系统识别界面打开/取消；确定性模拟识别结果验证只入草稿及过期结果丢弃。界面已查看，未运行完整测试矩阵。真实麦克风转写准确率不包含在这些检查中。

语音识别效果、实际手机麦克风和不同系统识别供应商仍需真机体验；不承诺所有 Android 设备都有可用系统识别服务。
