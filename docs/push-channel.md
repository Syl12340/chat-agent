# 自建加密后台接收（0.18）

2026-11-05。用户选择自建渠道并接受常驻通知；复用现有 ChatWire 加密端口及设备白名单，不接第三方账号或推送 SDK。部署状态见[发布记录](release-0.18.md)。

## 开启和停止

先在手机完成设备登录，在“主动关怀 → 这台手机的通知”点击“开启后台接收”，允许系统通知。旧包需要先通过应用内更新升级至 0.18.0-debug / versionCode 15。旧版本本机通知已开启，不代表升级后自动开启后台接收。

开启后持续显示“chat-agent 后台接收”通知，可从通知停止，或在面板关闭。关闭页面、退出 Activity 不主动停止该服务；退出登录、换服务器和显式停止立即取消本机网络。服务不是粘性服务，不添加开机广播，不绕过系统省电或自动唤醒；重新打开应用时，仅恢复此前已获准的接收，服务器禁用的订阅不会自行开启。

持续接收关怀、共同话题和到期提醒的通知预览，不推送普通聊天回答，不修改服务器已读状态。点击通知打开现有应用，具体内容仍在相应收件箱。锁屏公开版本隐藏正文；频道权限和锁屏设置最终由系统控制。

首次连接仅建立已有内容基线；明确关闭后重新开启也建立新基线，避免把停用期间的历史当新消息轰炸。服务重连、重启保留基线并补取新项目。每次最多最新 100 项、最多 32 个角色、编码后约 900 KiB；超限明确提示打开应用查看全部，不承诺无限历史补取。前后台共享受锁保护的持久 ID 去重，接收列表另有 256 个 ID 的有界 LRU，不靠跨角色全局时间水位过滤新到达项目。

通知遵守对应角色的安静时段和暂停设置，包含到期提醒；提醒的服务端到期状态仍按时进入收件箱。新设备首次连接时已经存在的内容不通知。收件箱删除不能撤回已投递到手机的副本，手机已显示的提醒不是投递确认或业务写入回执。

## 协议与鉴权

| 接口 | 行为 |
| --- | --- |
| GET `/api/push/settings` | 当前设备订阅状态，仅设备凭据；默认 false |
| PATCH `/api/push/settings` | `{ "enabled": true/false }`，显式保存当前设备订阅，不接受模型工具修改 |
| GET `/api/push/inbox?cursor=…&wait=20` | 已订阅设备的只读长轮询；cursor 为 64 位十六进制内容摘要，wait 为 0–20 秒；管理员凭据可只读检查但不创建在线租约 |

返回 `{cursor, items, truncated}`；每项为 `{id,role_id,kind,title,content,created_at}`，kind 为 care/topic/reminder。内容来自原角色收件箱，只取 ready 关怀、ready 话题及 due 提醒；不创建含正文的推送日志。cursor 不是服务端消息序号或确认，不保证跨请求原子快照。角色间不会合并身份或记忆，聚合只用于已批准的同一用户设备通知。

原生接收器通过固定同源接口与独立的短期设备会话工作，复用 Keystore challenge 签名，不循环注册、不使用管理员长期口令、不覆盖网页登录凭据。过期时续签一次，撤销、未批准和关闭订阅会停止接收；服务端长轮询期间约两秒复查鉴权和订阅。网络失败按 5 秒至 5 分钟退避并加抖动；响应限 1 MiB，不跟随重定向，不降级公网明文。

系统通知以本机预先持久化去重再提交系统通知的顺序处理，避免进程死亡后重复轰炸；提交失败、权限变化或截断仍可能漏通知，因此保留服务器收件箱为完整内容来源，不宣称 exactly-once 投递。

## 后台生成与成本

独立 30 秒服务端调度只有在至少一个**仍被批准、明确订阅且近 90 秒在线**的接收设备存在时，才补充后台自动关怀。在线租约不落盘，服务端重启后需重新连接。停止时尽力取消服务器订阅；网络失败仍会在租约到期后阻止新的后台关怀尝试，已经开始的尝试可能结算入收件箱。

后台关怀继续要求角色 enabled + auto_generate，沿用概率、每日尝试额度、最小间隔、暂停、安静时段及一次性结算。可选每日问候不叠在未读关怀/话题之上，超过两小时的每日问候不补发；明确事件跟进仍遵守原规则。订阅不会开启角色关怀、改变概率或自动添加提醒，也不把本机接收权限变成长期记忆/人设写入授权。

共同话题已有独立、显式开启的服务端调度，仍按原概率和共享预算执行，不以接收租约作为采集授权，也不因关闭通知而关闭采集。GET 收件箱不直接调用模型、搜索或修改源记录；通知内容准备好之后，接收和重连不增加模型调用。

## 数据和范围

`<data>/delivery/state.json` 版本 1，仅保存最多 128 个设备 ID 的 enabled 订阅；0600 原子替换，独占实例锁。在线租约只在内存。没有修改会话 v1、turns v1 或现有 life v2/v3 格式。回退 0.17 时保留该目录并停止新接收器；旧服务没有接口，原生会显示不支持，不自动重试或继续付费后台关怀。

Android 的 `remoteMessaging` 前台服务是本渠道承载方式，参见[官方服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types#remote-messaging)。常驻通知不保证 Doze、厂商省电、断网或系统强制停止时实时到达；Android 会延后后台网络，见[官方省电说明](https://developer.android.com/training/monitoring-device-state/doze-standby)。本次没有真机待机/耗电验收，后续厂商推送另行接入，不将这条自建渠道称为系统级可靠推送。
