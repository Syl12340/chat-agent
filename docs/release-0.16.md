# 0.16.0：概率关怀与人设候选审核

2026-11-04。服务端与 Android 更新通道已发布。本批同时包含此前未发布的 Harness 阶段 1–2、会话/最新轮删除，以及工作区已有的主题、直接网页搜索和语义重排改动。第三项内容作息/筛选漏斗未实施。

## 使用

- 在“主动关怀”中开启自动生成后，可设置 0–100% 的自动闲聊概率，默认 50%。既有启用状态、每日尝试额度、安静时段、暂停和最小间隔继续有效；默认不替用户开启关怀。
- 同一角色、同一天的自动闲聊机会只结算一次。未命中保存“本次未主动搭话”记录，不消耗模型尝试额度，不进入 rerank 或问候生成，不产生未读消息和通知。刷新、并发检查与重启不重抽；命中后先持久化预留尝试，再生成。
- 明确的事件跟进和手动生成不受概率闸门影响，继续受原有预算约束。关怀仍由应用可见时检查触发，没有新增后台推送或完整自动工具回合。
- 在聊天中请求持久调整交流风格，模型可用 `role_change_propose` 提交 PROFILE.md 候选。通过侧栏“角色变化建议”查看修改前后内容，批准后才生效；支持拒绝和删除记录。
- 候选按角色隔离，保存原文 hash、来源和 revision。原档案被修改后批准返回冲突，不覆盖新编辑。不能借此改 RULES.md、IDENTITY.md 或工具权限；当前运行回合保持既有人格快照，新请求加载已批准的修改。

## 数据与恢复边界

关怀文件 `<data>/life/state.json` 的读取器兼容 v1，写入使用 v2，增加概率、决定时间和 skipped 状态；旧二进制不保证能读取 v2。回退必须处理该文件，不能仅换回旧二进制。会话 JSONL 与 turns 台账格式未升级。

人设候选位于 `<roles>/.proposals/<role>/<id>.json`，每个角色最多 64 条，候选正文和原档案各最多 16 KiB；重复 pending 内容复用原记录。删除候选不撤销已经应用的档案，也不删除独立角色记忆。应用成功但记录结算失败时，重试审核可识别当前已包含建议，避免覆盖后续编辑；并未因此实现 Harness 阶段 3 的完整运行回执体系。

删除流程保留只允许硬删最新轮、生成中拒绝整会话删除的范围。本批修正保留摘要时日志重写的依赖顺序，避免重开时摘要先于消息而读取失败。不将聊天删除宣传为导出、备份、角色记忆和候选副本的全局擦除。
