## 1. Markdown 与 LaTeX

渲染顺序明确为：原始消息及归属 → 围栏/块级解析 → 行内与数学标记 → 可信渲染器 → 保留状态的挂载。普通代码、代码示例、引用和 chat-ui 声明不能互相吞并。组件来源哈希继续使用未经换行或 Markdown 归一化的原始 Content。

Markdown 采用 CommonMark 的块级/行内划分，补所需的 GFM 子集：表格、删除线和任务列表。任务勾选仅表示原文状态，不调用待办工具。表格局部横向滚动，段落与公式自动适配手机；代码块保留语言、复制、折叠和有界预览，代码高亮列为后续增强。没有完整规范测试结果前不宣称完整 CommonMark/GFM 兼容。

数学优先支持 `\(...\)`、`\[...\]`，同时支持 `$$...$$` 独立公式；单美元行内公式须定义转义与货币边界，不能把价格当公式。代码围栏与行内代码跳过数学解析；流式公式只有闭合后才排版，未闭合内容保留可读源码。

已采用 **KaTeX 0.19.1 本地数学渲染**，这是明确公式需求支持的一项前端依赖，Go 运行时仍独立实现。固定版本并在包内保存 JS 与 MIT 声明，不从 CDN 加载，不引入 Node 服务或前端框架。采用 MathML 输出，不加载 KaTeX CSS/字体，清除可选内联样式和 URL 属性，现有 CSP 保持不变；浏览器没有 MathML 能力时回退源码。

数学输出为常用数学排版子集，不执行完整 TeX 文档、外部文件、网络资源或模型自带宏插件。宿主固定 `trust:false`，设置 `maxExpand`、`maxSize` 及输入限额，每个公式使用独立宏环境；限制为单公式 ≤4 KiB，每条消息最多 16 个公式、数学源码总量 ≤32 KiB。解析异常按文本展示，错误信息也用 textContent，提供复制源码。数学布局仅在本机计算，不调用 LLM。

依据：[CommonMark 规范](https://spec.commonmark.org/0.31.2/)、[GFM 扩展](https://github.github.com/gfm/)、[KaTeX 配置](https://katex.org/docs/options)、[KaTeX 安全选项](https://katex.org/docs/security)。这些是设计依据，依赖固定版本和源码哈希见 `web/vendor/katex/README.md`。

## 2. 其它可视化结构

区分三种内容，避免要求模型为普通表格调用展示工具：

| 内容 | 表达与行为 |
| --- | --- |
| 普通 Markdown/公式 | 原回答直接排版；保留可复制的源码 |
| JSON 对象/数组 | 仅闭合的 json 代码块可切换树/源码视图，按需展开与复制；解析失败退回代码；不猜作工具请求或业务表单 |
| 声明式图表 | 继续用顶层 chat-ui 和静态组件目录；新增只读类型与既有四组件一致校验和降级，动作仍仅限原有两类答题 |

0.21 首批结构目录：

- **数据表 `table.data`**：列、行、固定文本/数字单元格；局部滚动及复制。建议最多 12 列、100 行、1200 单元格，仍受单声明 8 KiB 总限制。
- **柱状图 `chart.bar`**：有限类别和系列，显示轴、图例与“模型提供的数据”；建议最多 32 类、3 系列，无动态 URL、样式或表达式。
- **流程/关系图 `diagram.flow`**：有限节点和边，可信布局及 SVG，建议最多 32 节点、64 边；文本仅作标签，不支持点击执行、HTML 节点或模型提供的 SVG。采用项目自身有限 schema，首批不承诺 Mermaid 源码兼容。
- **JSON 树**：只读视图，建议最大深度 8、可展示节点 500、源码 32 KiB；超限回到有界源码预览和复制，不能让大对象阻塞聊天页面。

新增 chat-ui 类型须同步组件/响应 Schema、Go 与 JS 有限校验、模型指引、资源允许列表、SW 和 Android 完整性检查。保持 schema_version 1 的既有语义，旧客户端对未知类型按代码降级；不改变旧持久格式。具体 props 已随[Schema](schemas/chat-ui-v1.schema.json)及 Go/JS 校验固定；runtime 另检查行宽、数据长度与节点引用。

SVG/MathML/JSON 树均是展示结果，不能提供任意脚本、iframe、远程组件下载、外部图片请求或新增写工具权限。图表选择、展开和本地布局不发送消息。

## 3. 思考强度偏好记忆

这里记忆的是**发送参数偏好**，不是保存或展示模型隐藏推理。

- 同一服务器身份下，按 model ID 分别记住最后手动选择的 off/medium/high/ultra；记住当前模型，新会话和重启应用继承。
- 优先级：本次手动选择 → 同模型已保存档位 → 服务端合法默认。切换模型时恢复对应档位，不拿上一个模型的档位覆盖它。
- 模型暂时下线、列表加载失败或档位不可用时使用合法回退并提示；临时回退不覆盖旧偏好，恢复后仍可找回原值。
- 网页按当前 origin 和已认证身份隔离；Android 0.21/versionCode 18 通过原生桥按真实服务器和身份保存，跨启动时不依赖随机代理端口。相同 origin 下旧 `{model,thinking}` 只迁移一次。跨设备偏好同步另行按需实现，不把本机 localStorage 宣称成服务端同步。
- 历史消息保存的参数只作记录；回看不改当前默认。已入队、未知提交及同 ID 确认仍使用冻结的 model/thinking，不受新偏好影响。
- 退出登录清空本次页面状态；再次使用同一身份可恢复其本机偏好，不将别的身份的选择带入。不可用存储只影响记忆能力，不阻止正常聊天。

## 4. DSH / Codex / GPT 方向的 UI 优化

以下是本项目选择借鉴的组织方式，不承诺复制任何产品的当前完整界面或能力：

| 参考方向 | 落地到 chat-agent |
| --- | --- |
| DSH 式工作台 | 会话、工具过程与结果分区；工具日志默认简洁摘要，按需展开；右侧工作台查看同一结果 |
| Codex 式执行可见性 | 区分排队、思考/生成、工具执行、完成、停止和不确定；展示真实工具状态及错误，不把进度文案当完成回执 |
| GPT 式聊天阅读 | 统一段落宽度、标题/表格/公式/代码层级，简洁底部输入框，清晰模型/思考选择、图片预览、复制和回到最新 |

桌面保持导航—聊天—可收起工作台；手机保持连续聊天与大弹层。运行状态直接体现在消息或工具条，不新增“陪聊/解题/工作”模式切换。思考只呈现可验证的状态与已用档位，不编造推理时间或隐藏链路。

滚动和焦点由用户当前操作决定：上滚阅读、编辑填空、拖动滑块时不自动跳底；刷新尽量复用原节点。展开继续移动同一个实例，普通聊天、草稿、已冻结请求与角色隔离沿用现有机制。手机输入、触摸目标、深浅主题和键盘可达一起处理，少堆常驻按钮。

## 5. 最小交付检查

只保留三条贯穿流程，相关代码变化时运行，不构建全排列矩阵：

1. 一条混合回答：Markdown 表格/嵌套列表、行内及独立公式、代码、JSON 树、新旧图表，连同未闭合/非法/超限输入检查展示及源码回退；没有额外网络或模型调用。
2. 一条参数流程：按模型选档 → 新会话 → 重载/应用重开 → 切回模型；加入暂时不可用回退和冻结请求确认，验证偏好恢复而历史参数不变。
3. 桌面与 390 px 视口：同一内容阅读、工具展开、工作台收回、局部输入/滑块保留、深浅主题与焦点。公式及宽表只在自身滚动，不让页面横向溢出。

使用隔离 demo 和少量关键断言，不默认重复付费生成或要求独立审查。真机/PWA/真实模型呈现质量继续单独记录，未实际检查不标记通过。
