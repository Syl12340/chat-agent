# 0.21.1 聊天恢复与失败原因

2026-11-06。状态：实现及关键检查完成，准备发布。服务端 **0.21.1**，Android **0.21.1-debug / versionCode 19**，沿用原包名、签名与身份。

## 排障结论

用户报告“LLM 无法回复”。线上服务健康、无会话读取失败；最近三条生成失败且无可见回复，随后队列停在 paused。旧版没有为这些队列失败保存具体原因，不能追溯认定为参数、额度或输出截断。

核对用户提供的[ECNU 模型说明](https://developer.ecnu.edu.cn/vitepress/llm/model.html)和[思考协议](https://developer.ecnu.edu.cn/vitepress/llm/thinking.html)，现有 Max 的 low/high/max 与 Plus 的 low/medium/xhigh 映射一致。诊断时模型接口、真实 Go 传输、空会话完整工具目录均可正常回复；在用户明确授权的一次隔离历史请求中，也收到完整 stop 回答。

已在确认没有 queued/running 请求后，解除线上遗留暂停。没有重发旧失败消息，没有修改原历史、角色、模型、密钥或预算；原失败的确切上游原因仍未确定。

原始日志读取与未获授权的历史诊断先被自动审批阻止，均未执行。随后采用脱敏结构统计和空会话；用户授权后只执行一次历史模型诊断。历史、回复和隐藏推理正文未导出，服务器隔离副本随诊断完成清理。合计五次有界实时诊断请求，发布检查仅只读，不再调用模型。

## 修复

- 暂停且无排队项时显示“恢复聊天”，解决原按钮被隐藏的问题；有排队项仍显示“继续队列”。存在未知提交时先确认该提交，再允许恢复。
- 模型错误改为宿主定义的类型，区分 HTTP 拒绝、鉴权、限流、连接、流中断、空回复与输出上限；超时单独提示。保留片段，不把截断输出提交成完整回答或执行不完整工具。
- 队列与旧流式入口显示固定的可读失败原因；日志仅写固定类别，不写上游响应、用户内容、密钥或隐藏推理。
- 恢复只解除暂停；失败请求不自动重试，同 ID 提交语义保持，模型与思考参数预算均不变。

## 最小验证

`TestModelFailureBoundary` 验证 HTTP/SSE/截断/空回复与取消原因，检查无私有响应泄漏和额外请求；`TestFailureReasonAndEmptyQueueRecovery` 验证限流错误保存、空恢复零重放、新请求一次完成。相关互动及多模态思考流程通过。

隔离 demo 浏览器点击空队列“恢复聊天”后历史/队列仍空，新消息可正常处理。Go 构建、vet 与 Android 离线构建通过。没有真机安装验收，没有再次执行线上用户问题。
