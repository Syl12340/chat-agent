# chat-agent 本地 Agent 改进实施指南

更新日期：2026 年 11 月 28 日。评估基线：`723845a`，工作区在本次文档编写前无未提交改动。接手时重新读取 HEAD、AGENTS.md 与相关 diff，若实现已变化，按实际行为调整本指南。

本指南指导本地 Agent 完善 UI、Harness、仿生陪伴、工具调用、持续执行和实际交付。评估时技术基线是 Go Core、原生 Web 与 Kotlin，优先完成正常使用流程，按依赖实施并合批验证发布。编号表示工作依赖，不表示版本或工程排期。

2026-11-29 补充：技术选型与 DSH 交付边界以 [架构改造与体验实施方案](dsh-architecture-implementation-plan-2026-11-29.md) 为准，其中建议渐进采用 TS/React/Vite、按领域使用 SQLite 和成熟文档处理组件。本文的持久性、授权、来源与状态约束继续有效，先修缺陷不等待技术栈迁移。

## 结论与使用范围

当前已进入能力整合阶段。任务结构、运行中补充、卡片复用和课件原件都有第一版实现，下一步应集中完成持久性、鉴权、真实状态和用户操作的一致性。每项修改都要回答：用户操作能否保留，结果能否核实，刷新或换端后能否继续。

这次是源码与测试内容评估，没有执行生产操作、真实模型请求或手机验收。编译通过、存在测试、线上已部署、真实场景通过是四种不同证据。版本号本身不能证明后三项。

本指南中的新接口与扩展字段属于设计要求，实施者应先复用现有契约。不要直接把示例当成当前可调用 API。源文件链接用于定位，具体函数与字段以接手时源码为准。

## A 优先修复当前实现的正确性

### A1 补充输入必须持久接纳

入口：[turn_submission.go](../internal/api/turn_submission.go)、[agent.go](../internal/probe/agent.go)、[assembly.go](../internal/probe/assembly.go)、[turns.go](../internal/api/turns.go)、[supplement_test.go](../internal/api/supplement_test.go)。

当前顺序是 Enqueue、AddSupplement 到内存、Remove 队列记录。`takeSupplements` 消费后只追加到本次模型请求，没有持久写回历史，也没有保留给后续 assemble。由此存在以下路径：

- 返回 current_task 后崩溃，补充既不在队列也不在历史。
- 注入一次后继续调用工具，下一模型 step 可能失去补充。
- 最后一次模型请求期间收到补充，模型直接结束，没有下一次 assemble 消费它。
- Remove 失败时内存仍已接收，后续队列也保留，可能执行两次。
- 原 request ID 被删除，同 ID 重试失去原有去重凭据。
- 补充只携带 Content，图片、Origin、模型选择和结构化回答等信息没有随之保存；当前接纳条件没有绑定活动 run 的来源与受众。

实施要求：保留原 request 记录，增加接纳目标 attempt/turn、内容摘要、来源、状态和接纳序号。先持久记录，再通知运行时。模型 step 边界原子领取，记录已纳入哪些补充；每次后续上下文都保留这些真实用户输入。补充持久化为真实消息并获得 message ID，更新工具输入证据，不能仅靠英文前缀临时伪装成消息。

将接纳与生效区分为 received、accepted、applied，字段名称可沿用现有约定。运行已结束或没有下一个 step 时，原请求仍可进入下一轮并明确回执。重复提交返回原接纳结果，不重新执行。第一版若只支持文字，应在 API 明确拒绝带图片或互动答案的 supplement，不能接受后静默丢弃。

共享 App/QQ 会话不代表补充可以扩大当前 run 权限。来源、受众与执行授权不兼容时进入下一轮；用户改变目标或路径后，旧批准票据不得授权新参数。前端的“补充当前任务”仅在运行中出现，发送后复位，失败重试保存该意图，不增加长期对话模式。

完成标准：以同一个 request ID 覆盖重复提交、连续两步消费、最后一步到达、重启恢复，并验证消息恰好保留一次。已有三种提交分支测试只证明分支选择，不能替代这些行为。

### A2 设备登记不能覆盖另一把已受信任的密钥

入口：[store.go](../internal/deviceauth/store.go)、[slots.go](../internal/deviceauth/slots.go)、[device-auth.js](../web/device-auth.js)、[DeviceIdentity.kt](../android/app/src/main/java/dev/chatagent/ai/DeviceIdentity.kt)。

Web 原生桥判断已修正。悬空 slot 启动失败已通过忽略映射缓解，但两份文件仍不是事务。

当前 register 在已有 slot 指向 pending 记录时直接构造新 pending 并写入 `updated[id]`，尚未先检查这个 id 是否已属于另一条 approved/revoked 记录。公开登记接口中，公钥不等于持有私钥的证明，不能允许该分支覆盖既有信任状态。claim 分支也需在统一校验后结算，不能被 pending 替换分支提前返回绕过。

先修局部不变量：已有 key 的状态和所属设备只能通过有权限的操作改变；匿名请求不能用另一个 slot 把它降级、替换或绑定。限制 slot 数量和一个 key 可关联的映射数量。恢复时若补偿失败，应返回明确维护状态，避免磁盘和内存继续分叉。

随后确定一个权威设备快照，包含稳定设备 ID、凭据、slot 映射和 revision，使用同一原子提交；若为旧版回退保留 sidecar，则采用有版本的选代/提交记录，不把简单忽略悬空映射描述为事务恢复。新增字段前检查旧读取器的严格反序列化，安排格式迁移和数据回退。

产品标准是同一 App 正常切地址、端口、协议、重启和升级不新增设备记录。Android 的稳定标识只帮助定位设备，挑战签名决定信任。浏览器不同 origin/profile 的隔离不能靠 UA、型号或屏幕摘要自动突破；优先固定浏览器访问源，跨入口使用经验证的关联流程。不能承诺只凭浏览器系统信息识别同一物理设备。

已有 114 条历史 pending 的归属和当前数量需重新只读核对。清理前备份并生成候选清单，可归档过期未批准登记；不要直接把所有 pending 当作已证明的重复设备，也不要因名称相同合并 approved 凭据。

最小验收：已批准旧 key 不能被匿名 pending 替换请求覆盖；同 slot 重复登记数量稳定；失败/崩溃后能加载一致数据；Web 与 App 各走一条真实登录路径。

### A3 成果契约必须对接真实工具和下载接口

入口：[contract.go](../internal/turns/contract.go)、[contract_test.go](../internal/turns/contract_test.go)、[workspace/plugin.go](../plugins/builtin/workspace/plugin.go)、[image_jobs.go](../internal/api/image_jobs.go)、[server.go](../internal/api/server.go)、[app.js](../web/app.js)、[courseware.js](../web/courseware.js)。

当前投影只识别少数工具名并解析 event.Output；`/api/images/{id}` 的推导路径与已注册的 `/api/sessions/{id}/images/{image}` 不符。测试使用自己构造的 payload，不能证明真实工具结果能正确投影。图像 submit 返回作业并不等于图片已生成。

先逐项对照真实工具返回结构、异步完成回执和注册路由。成果来源应是结构化回执及对应存储，错误输出、截断 JSON 和自然语言不能作为文件存在证据。下载路径由宿主按作用域生成，不能由工具返回任意 URL 直接设置成 href。

普通网页使用 Bearer 请求，直接 `<a target="_blank">` 不会自动带 API Authorization。新成果链接与课件“看原页”都要走已有鉴权 transport 获取，再以安全预览或下载方式交付。优先复用现有附件下载逻辑；使用 Blob 时保证释放、大小限制、敏感类型隔离。需要一次性下载票据时单独设计作用域和期限，不能把长期令牌放 URL。

完成标准：通过实际 workspace_share/图像完成回执生成卡片，在普通 Web 和 Android 正常取回字节并核对 hash；跨会话或撤销授权后拒绝。检查一次真实 401/404，不能只断言链接字符串存在。

### A4 PDF 不能把部分文本当成完整课件

入口：[pdf.go](../internal/courseware/pdf.go)、[store.go](../internal/courseware/store.go)、[courseware.go](../internal/api/courseware.go)。

当前提取器扫描 stream 标记并读取部分 literal string。它跳过 hex/CMap 字符，常见 `[(A) 20 (B)] TJ` 数组也未按 PDF 语法解析；只要另有一段可提取文字就会成功返回，不能证明全篇完整。单 stream 的 LimitReader 没有额外字节判断截断，多 stream 先汇总还缺总解压预算与取消控制。

立即将当前能力标记为有限提取，返回 extraction_status、warnings 和可验证的页信息。检测不支持编码、截断或解析异常时显式降级，模型收到“资料不完整”的上下文。不要根据全篇非空就宣称提取完整，也不要把当前扫描顺序当页顺序。

面向中文课件使用成熟解析/渲染组件，属于有明确产品需求的依赖。落地前核对维护性、目标平台、许可证和进程隔离，固定版本并更新 notices。将提取放入有资源预算的作业，输出按页文本、页数、状态及 SourceRef。扫描件另走可选 OCR，不暗中调用付费服务。

原件保存已有实现，但 Add 在提取成功后才保存原件，因此解析失败的资料仍无法留存供后续处理。改为原件入库、提取作业、发布可读索引三阶段。旧资料缺原件时明确显示补传需求，读取原件时核对大小/hash。原件打开也不等于 PDF/PPTX 页级预览已经完成。

最小样例：中文 CMap、TJ 数组、混合可读与不可读页、扫描件。重点断言不静默漏页及原件保留，不做无限格式矩阵。

## B 完善任务和持续执行

入口：[contract.go](../internal/turns/contract.go)、[turns.go](../internal/api/turns.go)、[agent.go](../internal/probe/agent.go)、[executor.go](../internal/probe/executor.go)、[harness-storage-contract.md](harness-storage-contract.md)。

当前 Task 是 turn 的展示投影，Run.ID 仍等于 turn.ID，Operation.ID 来自工具事件 ID。它是统一查询形状的起点，尚未表达一个任务多次 attempt 或工具 call 与业务 operation 的区别。先保持新查询接口兼容，再补字段和来源映射。

| 对象 | 要表达的事实 | 权威来源 |
| --- | --- | --- |
| Task | 用户目标、修正、完成条件、当前进度 | 明确的任务/输入登记，初期沿用 turn 关联 |
| Run | 一次模型执行及其终止原因 | runlog attempt 与规范 turn 状态 |
| Operation | 已发起动作、参数摘要、实际执行端和结算结果 | 已有 operation 记录和业务回执 |
| Artifact | 存在的成果、版本、hash、授权读取方式 | 文件/图像/课件存储及回执 |

保持现有 manifest 选代规则。history、turns、运行事件、业务存储各有权威边界，不能宣称现有 events 可以重放重建一切。展示投影可重算，未知副作用必须查询业务端，不能自动重放。

扩展运行状态为能区分 running、waiting_approval、waiting_job、cancel_requested 和真实终态的结构，具体命名与旧状态兼容。页面关闭只取消订阅；用户停止提交取消请求，最终是否停止由执行端确认。重启后恢复可查询作业，无法核实的操作保持 unknown。

修正连续 loop 的三个边界：

1. 相同查询不等于重复副作用。job status 允许按建议间隔等待；写入通过幂等键防重复。当前相同批次强制 final 的逻辑不能误杀正常轮询。
2. 循环中按实际上下文预算压缩，保留当前目标、补充、未完成操作与成果引用。不能切断 assistant/tool 批次，也不能将摘要恢复为授权证据。
3. 分开模型请求、短工具、持久作业、确认等待的期限。运行挂起后保存状态并释放 worker，不用一条长 goroutine 或无限模型请求维持等待。

当前 failedSideEffects 只按工具名称及 Error 计数。命令失败可能在 JSON status 内，而不是 Error；先失败后成功也可能被持续算失败。将副作用类型、业务状态、重试/替代关系和成果验证放进回执，再计算 task outcome。普通聊天可直接完成，文件任务需有对应成果，外发需有投递结算。

最小验收：两次相同状态查询后作业完成、用户补充改变后续两步、取消后确认真实终态、已提交操作在重启后不重复。使用假 provider/执行器即可，真实模型只验证确实依赖模型选择的部分。

## C UI 和 GenUI 的下一步

入口：[app.js](../web/app.js)、[desktop-workspace.js](../web/desktop-workspace.js)、[turns.js](../web/turns.js)、[presentation.js](../web/ui/presentation.js)、[study_surfaces.go](../internal/api/study_surfaces.go)。

当前复用比较 className 与 textContent，仍先构建全量 fragment，再搬旧节点并 replaceChildren。相同文字不保证属性、链接、事件绑定或互动 revision 相同。计数只能证明进入复用路径，不能证明焦点、选择区和触摸稳定。后置附加的模型标签、动作和成果也应纳入稳定更新规则。

采用按消息 ID 维护的视图控制器，分别更新文字、思考、工具状态和成果。以业务 revision/内容摘要决定更新，保留用户展开、内部滚动、选中文本和编辑中答案。新增消息插入，已有节点不为刷新而脱离 DOM。只对已稳定的长历史考虑窗口化，先保住引用锚点。

阅读跟随单独维护：用户上滑或操作思考/工具区后进入阅读状态；新增文字只显示“新内容”。主动点回到底部或明确的新会话行为才恢复跟随。图片加载、键盘弹起、展开工具均不能擅自复位。

`applyTurnHistory` 新增每次请求 tasks。将 tasks 纳入同一响应 revision，或并行查询后在同一 session/auth epoch 检查通过后提交。失败时不能把别的会话缓存当当前任务。当前消费主要用于成果链接，任务卡其他状态也应逐步改读规范投影，避免两套推导。

界面保持对话、任务、成果三层。角色和记忆保留手动编辑，但从助手资料和消息动作进入。技术管理项集中到高级设置。运行中的补充选项属于一次发送行为，不重建显式“陪伴/解决问题”模式选择。

GenUI 优先做任务进度、成果预览、课件作答。View 负责展示，业务 Action 携带 entity ID、expected_revision、幂等请求 ID；宿主验证权限与版本后提交，再返回新 View。临时 UI effect 不承担业务成功事实。换端恢复来自业务记录，不能只依赖浏览器 Map。

完成标准：一次离线假数据驱动的浏览器流程同时验证滚动、详情展开、答案输入、成果打开和会话切换。扩展现有脚本前检查其是否会创建真实会话并调用线上模型，不直接运行线上 smoke 作为普通 UI 测试。

## D 工具能力与双端执行

入口：[registry.go](../internal/probe/registry.go)、[plugin_tools.go](../internal/api/plugin_tools.go)、[host_tools.go](../internal/api/host_tools.go)、[workspace](../plugins/builtin/workspace/plugin.go)、[local_agent.go](../internal/api/local_agent.go)。

将完整插件目录与每 step 暴露的工具集合分开。当前 MaxTools 在注册入口限制总数，仅增加 Available 过滤仍解决不了超过注册上限的问题。先提供轻量能力发现和按需加载，再按权限与任务选择工具；模型可发现遗漏能力，不能靠关键词路由把能力永久隐藏。

在现有工具元数据上增加实际使用需要的副作用类别、观察型调用标识、幂等/查询能力和成果 schema。可恢复错误返回 retryable、retry_after、operation_id 和下一步建议。未知写入结果要求先查询。只对明确声明并发安全的读取做有界并发，写入保持作用域内协调。

电脑本地启动 Core 即能执行已授权本地能力，云端使用服务器沙盒。远程操作另一台电脑才使用现有执行端连接。普通用户只看到执行位置和作用范围，不需要先维护多套绑定。

Linux 短 shell 继续使用现有 Landlock/seccomp，隔离不可用时拒绝；长命令进入可查询作业。任务临时目录接收用户选定输入，成果持久化后再清理。任务级资源限制应与聊天服务配额分开。授权可覆盖指定任务目录内的连续处理，主机维护、修改原件和外发保持独立边界。不要把不可靠的 shell 字符串黑名单当隔离。

记录工具调用中的参数错误、无效重复、恢复动作、等待时间、成果是否可取，使用合成样例跑一次模型任务获取反馈。反馈用简短结果摘要，不要求模型输出隐藏推理，不把用户原文或密钥写入诊断报表。

## E 仿生聊天与主动陪伴

入口：[care_continuation.go](../internal/api/care_continuation.go)、[proactive.go](../internal/api/proactive.go)、[push.go](../internal/api/push.go)、[companion/care_continuation.go](../internal/companion/care_continuation.go)、[life.go](../internal/companion/life.go)。

保留已有连发合并、多气泡、相似话题去重和显式沉默。续聊仍依赖词句匹配与时间窗口，后台 run 仍限制一次且无工具，因此接下来应增加有来源的语义意图。

让正常对话的模型在有价值时提出待跟进事项，包含 source_message_id、主题、行动理由、not_before、expires_at、失效条件和类型。它是短期意图，不自动升级为长期记忆或正式提醒。用户全局陪伴许可与具体事项的跟进约定共同约束执行。

调度顺序：来源仍有效 → 用户偏好和安静时段 → 未读与重复 → 预算/近期触达 → 候选价值 → 必要时调用模型。明确提醒不受闲聊概率随机取消。无候选就不调用模型，也不为了“像活人”高频唤醒。

后台使用同一 Harness 与模型路由，但使用更窄的工具集合、独立预算和来源范围。允许必要的读取/检索/作业查询；长期记忆、人设和其他写入继续走原有审核及授权。决定沉默时保存简短结构化原因，不伪造一条用户消息。完成前再核对来源是否过期、用户是否已回复。

区分“少一点”“这个话题结束”“暂停今天”和“关闭主动陪伴”。当前分类间隔已做区分，不重复实现；继续核实 CareKindMuted 中 less 达阈值即静音的产品语义。降频与暂停应有不同状态和恢复入口。

用户未回复不能等同于反感；允许安静，不追加机械追问。语气来自可编辑角色和明确偏好，不生成心理诊断标签。多气泡逐段交付时，用户新输入应让尚未发出的过时片段重新判断。

最小验收：明确约定得到跟进、已结束话题不再触发、候选失效后不发、低价值候选沉默、负反馈只作用于对应类别。用少量固定时间与随机源的样例保证可复现。

## F 记忆 学习与跨端联动

角色和记忆继续支持手动编辑。消息旁增加来源查看、纠正和遗忘，复用现有审核、revision 和上下文 floor，避免旧摘要重新引入已删除事实。角色卡描述稳定表达，任务状态记录工作进展，短期陪伴意图记录待接续事项，减少重复写入多个存储。

学习链路按原件版本、提取作业、页级 SourceRef、讲解、题目版本、作答、评分与复习推进。已有 quiz 和 surface 作为视图保留，作答/评分成为独立业务记录，带来源与幂等提交。评分依据和模型版本可查，刷新不泄露或重置未提交答案。

QQ 与 App 继续使用既有同一私聊会话映射，不另建默认机器人对话。共享上下文不等于把每条 App 回复广播到 QQ。来源决定回复目的地，主动消息按显式渠道偏好投递。权限依赖可信入口和当前 run，QQ 文本不能自动继承 App 的 shell 批准。

AstrBot 适配器当前逐条发送气泡后统一 ack，后续失败时无法完整表达先前已送达部分。增加 delivery part 的稳定标识、状态和平台回执，能确认已送达的部分不重复发；平台无法证明结果时保留 unknown。图像、附件、表情包归一到媒体/产物契约，下载与外发分别授权。

ComfyUI 使用已存 renderer/job ID 恢复查询。现有 lookup 主要读取本地记录，应补实际后端状态核实。提交成功但 ID 未保存是独立崩溃窗口，需要后端幂等请求或查找能力；若不支持，就明确 unknown 并禁止自动重提。隧道在线与 ComfyUI 就绪分别展示。

- App 与 QQ 接续同一私聊，部分投递不整批重发，陪伴只在合适候选上触发。
