# 0.4.0 陪伴对话核心

当前 0.9.0 已将偏好工具改为模型自主选择，不再用前缀、标点或关键词决定工具是否出现；原文只做来源核对，版本和角色校验保留。[当前架构](model-driven-runtime-0.9.md)。以下保留初版说明。

本轮实现陪伴偏好与对话策略，不改变 Go/Kotlin 技术栈，不增加第三方运行依赖。借鉴方向见[迭代计划](feature-plan.md)，代码独立实现。

## 使用方式

侧栏“陪伴偏好”可以设置当前角色怎样称呼你、回复长短、说话语气、给建议和追问的习惯。保存后，同一角色的后续请求和新会话都会加载；其他角色不共享。选择“跟随角色设定”保留原有角色 Markdown 的默认风格。“恢复角色默认”只修改表单，点击保存后才生效。

也可以直接说“以后叫我小李，回复短一点”。明确的长期修改会向模型提供受限的 `companion_preferences_update` 工具；只有工具成功才能确认已保存。首版保守识别以“以后、今后、从现在起、默认、请记住”等开头、涉及交流偏好的短指令；带引述、疑问、举例或临时限定时不暴露此工具。不明确的表达仍可自然交流，长期设置使用偏好面板修改。

0.7.1 起不再显示“这一条想怎么聊”选择器，由模型根据当前话语和上下文自然判断如何回应。可以直接说“这次详细讲”“先别给建议”，临时要求不改写长期偏好；不增加分类调用。[更新说明](adaptive-chat.md)。

小伴的常驻策略强调围绕具体事情倾听、自然接续、需要时共同想办法，并避免重复问候、密集追问或编造共同经历。已有自定义人格文档保留；不会被部署覆盖。情绪只作为当前对话理解，不创建永久情绪标签，也不额外调用情绪分析模型。

## 实现

- `internal/companion`：结构化偏好、持久化、修订冲突及对话策略。
- `internal/api/companion.go`：受鉴权保护的读取/修改接口及限定当前角色的偏好工具。
- `internal/api/knowledge.go`：每轮固定加载陪伴偏好，相关已审核记忆继续按查询检索；新工具结果优先于本轮开始时的旧偏好快照。
- `web/companion.js`：轻量设置表单，过期页面收到 409 后重新打开，避免静默覆盖。

存储为 `<data>/companion/<role>.json`，目录 0700、文件 0600。版本为 1，包含 role_id、revision、preferences 和更新时间。使用独占实例锁、同步后替换；写入成功才返回新状态。不修改已有聊天 JSONL 格式；降级旧程序可以忽略此目录，但不再应用这些偏好。

```text
GET   /api/roles/{id}/companion
PATCH /api/roles/{id}/companion
```

PATCH 必须携带当前 revision，修改字段为 preferred_name、reply_length、tone、advice、questions。称呼最多 40 个 Unicode 字符，拒绝控制/格式字符、尖括号和换行；其他字段为枚举。首次默认 revision 为 0，保存变更后增加。相同值不重复增加 revision。

```json
{
  "revision": 0,
  "preferred_name": "小李",
  "reply_length": "short",
  "tone": "warm",
  "advice": "ask_first",
  "questions": "light"
}
```

消息接口保留可选 mode：auto、listen、chat、solve 以兼容旧客户端和队列请求；0.7.1 起这些字段不再形成强制风格指令，新网页统一提交 auto。偏好工具需要复制当前用户原文为 evidence，校验当前快照修订号和存储修订号；不能指定另一个角色、修改规则或扩大工具权限。偏好值以 JSON 参考数据提供，不拼成用户可控制的系统指令。

交流风格结合当前用户表达和上下文判断，再参考保存的偏好、角色默认；服务端工具权限和固定约束始终有效。普通事实仍沿用已有 memory_write 候选审核机制。恢复偏好默认值不等于删除聊天、摘要或记忆中的相关内容。

## 验收范围

新增一条 `TestCompanionPreferencesLifecycle`，覆盖偏好工具、设置修改、版本冲突、非法字段、新会话加载、临时模式与角色隔离、重启恢复。已有记忆验证改为读取新的上下文结构，仍检查已审核事实及角色隔离。只运行受影响的 API 和运行时检查，不运行完整矩阵。

2026-11-02：受影响的 5 项 API 和 4 项运行时检查通过；新增仅 1 项陪伴集成流程。隔离 API 35 模拟器完成偏好保存、当次模式发送后复位、聊天修改称呼、新会话沿用及角色隔离，无网页错误。使用服务器隔离实例的 ecnu-max 完成三段短场景：

- 倾诉并要求不提建议：回应工作消息反复打断的疲惫，保持倾听。
- 明确请求十分钟内能做的小办法：给出暂时静音并休息的具体建议。
- “以后叫我小李，回复短一点”：实际调用偏好工具成功，新会话面板读回“小李”。

隔离验收没有改写正式用户偏好或聊天，完成后停止验收进程。仅使用这三段真实对话验证语言体验，不将单次通过宣称为稳定质量保证。演示模式仍是明确标注的固定回复，不能用于评价陪伴语言质量。
