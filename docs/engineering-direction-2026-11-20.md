# chat-agent 工程方向评估

日期：2026-11-20。基线：0.7.19 工作区。本文只规定工程方向、边界和完成信号，不安排工期或拆发布批次。

## 结论

项目不需要换掉 Go，也不需要再造一套桌面 Agent。正确路线是把现有 CA Core 固化成**同一内核、两种运行配置**：电脑本地端像 DSH Web 一样打开即用，云端负责手机、常驻陪伴与 IM。下一阶段的重点不是继续增加设置入口和零散工具，而是完成四件事：

1. 让电脑本地版成为可安装、可更新、可恢复的正式产品，而不只是一个可运行 EXE。
2. 把 Harness、Operation/Receipt/Artifact、SourceRef 和 GenUI Action 收敛成少量稳定契约，停止各业务自行发明状态。
3. 在强制隔离可验证后开放本地命令编排；隔离不可用时继续拒绝任意 shell。
4. 围绕仿生陪伴、课件学习和 QQ 私聊做真实闭环，用真实样本与回执改善质量，不再用更多管理页代替能力。

## 现状判断

当前仓库约有 262 个 Go 文件、96 个 Go 测试文件、28 个 `internal` 包、17 个内建插件、37 个 Web JavaScript 文件和约 115 个 API 路由注册。它已经不是轻量原型：

- Harness 已是持续 loop，零 turn/tool 上限，仍受取消、总超时、逐工具超时、重复调用和批准约束。
- Core 已拥有会话、角色隔离、候选记忆、来源/受众、审批、运行记录、业务回执和模型配置。
- Operation/Receipt/Artifact 已用于远程执行；SourceRef 已覆盖文本范围与 PPTX 幻灯片；View/Action 已能承载持久学习面板。
- 插件宿主已有 manifest、依赖、授权、生命周期、Tool 与 Service，但多数产品能力仍直接堆在 `internal/api`。
- Web 已具备可用聊天体验和多种面板，但 `app.js`、`style.css` 与 `index.html` 仍分别约 83 KB、73 KB、43 KB，页面状态和管理入口继续集中会快速增加修改耦合。
- 0.7.19 新增电脑本地运行配置、无感本机令牌、本地模型配置、默认工作区和经批准的原子文件写入；Windows 任意 shell 尚未开放。

因此当前主要风险不是“缺功能”，而是**已有能力的边界开始重叠**：云端执行端与本地运行时概念混淆、API 组合根过大、业务状态存在多套相似结构、Web 壳层继续膨胀、外部渠道缺真实账号证据。

## 目标架构

### 1. 同一 Core，两种运行配置

保留一个 Go Core，不复制会话循环：

- `desktop-local`：只监听 loopback，本机令牌无感进入，本机数据目录和工作区，本机保存模型凭据；不依赖云端在线。
- `cloud`：加密手机入口、设备 challenge、常驻调度、IM、服务器工作区和后台投递。
- `remote-endpoint`：仅在用户明确需要云端调电脑时启用，继续使用 operation/receipt/artifact；从产品主路径和常驻菜单退出。

运行配置决定可注册能力，不在业务代码里到处判断平台。桌面与云端共用会话、Harness、插件和 GenUI 契约，差异集中在启动装配、认证、更新、沙箱与触发器。

### 2. 稳定四组核心契约

不建立一个万能大对象，只统一真正重复的部分：

- `ExecutionContext`：principal、audience、session、role、workspace、runtime profile、授权版本。
- `Operation / Receipt / Artifact`：执行、服务器维护、文档转换、图像任务共用身份、状态机、结果与产物；提交不确定时查询同一 operation，不自动重跑。
- `SourceRef`：文档版本、hash 与定位器；扩展 PDF 页、DOCX 段、图片区域时保持旧引用可解析。
- `View / Action`：学习卡、任务卡、审批卡共用 revision、幂等动作、来源有效性和客户端降级。

业务存储可以独立，但不能再各自定义“差不多的 operation ID、状态、过期和下载权限”。

### 3. API 从组合根拆成领域模块

`internal/api/server.go` 继续做进程组合根和公共中间件，但路由注册按领域拆分为小型 registrar：chat、identity、models、memory/life、learning、operations、channels、updates。每个模块显式声明依赖，不直接拿整个 `Server` 的所有存储。

这不是为了目录美观，而是降低三个风险：桌面 profile 意外暴露云端管理接口；插件停用后残留路由/提示；单个功能修改需要理解 115 个路由和 87 个 API 源文件。

### 4. 插件化保持克制

Go Core 继续统一持有身份、会话、授权、结算和持久迁移。适合插件化的是可独立声明、启停和降级的能力：Tools、ContextSources、PromptSections、Providers、Triggers、Renderers。不要把每个内部函数包装成插件，也不嵌入 Cordis 运行时。

下一步用真实能力验证扩展点：

- Provider：本地/服务器模型凭据与能力发现。
- Trigger：主动陪伴和服务器巡检共享触发预算、去重与受众。
- ContextSource：记忆、课件和共同活动按预算提供引用，而不是到处拼 system prompt。
- Renderer：学习答题、任务进度和审批卡声明式渲染；插件不得注入任意 DOM/脚本。

DSH 可按许可证直接移植成熟契约、视图和执行逻辑，但每个实际引入文件继续记录上游 commit、源路径、改动和分发义务。

## 四条产品主线的工程落点

### 仿生聊天与主动陪伴

不再增加“模式”开关。由 LLM 根据系统工具、当前消息、获准记忆、节奏偏好和触发来源决定是否接话、分段或沉默。

工程上建立一个小型回放评估集：连发、换题、纠正、晚安、低落但非危机、主动消息回复、QQ 短句等真实样本。检查是否漏答、追问过多、错误召回、机械分段和主动打扰。它是开发诊断，不建设大而全测试矩阵，也不保存未经同意的私人原文到仓库。

主动触发继续先本地规则/概率/配额，再调用模型；反馈只影响同类触达，不推断人格或关系。表达节奏与语义气泡属于呈现层，业务提交和工具结果保持原子。

### DSH Harness 与电脑本地 Agent

首先补正式桌面发布面：版本清单、SHA-256、增量或完整下载、原子替换、失败回退和数据目录兼容检查。打开即用不等于静默自更新；下载和切换必须可观察。

自由 shell 采用 `SandboxBackend` 能力接口，而不是在工具里硬编码 PowerShell：后端报告文件、进程、网络、资源和提权约束。只有验证通过的后端才注册 `workspace_exec`；否则仅保留 list/read/search/write/share。命令可由模型编排，但批准绑定实际 argv/脚本 hash、工作区、网络与期限。

跨端接续不做“自动镜像整个数据库”。先支持导出/接入一个选定会话或一个 Artifact Bundle，带来源、受众、角色、消息 ID、operation 和 hash；冲突保留两份，不用时间戳覆盖。长期记忆仍走候选审核和角色隔离。

### UI / GenUI / EduWork

Web 不立即迁移框架。先把 `app.js` 的会话编排、设置和导航拆为明确模块，引入一个最小状态订阅层；CSS 按 shell/chat/workbench/components 分层，删除重复规则而不是再叠覆盖。侧栏只保留会话与高频入口，模型、记忆、渠道、运维、课件管理进入统一设置或按上下文出现。

GenUI 继续坚持服务端声明、客户端白名单渲染。优先补：PDF/扫描页 SourceRef、独立答题/评分/错题 Receipt、批注侧聊与可导出学习成果。资料处理改为可查询 operation；原件、提取文本、页图和结果分别成为 Artifact，失败可以定位到页和提取器版本。

### QQ 等 IM 联动

CA 继续唯一持有模型、Harness、记忆和结算；AstrBot/Aurabot 只提供 transport、平台身份和媒体适配。先完成真实 owner 私聊文本闭环：验签、绑定、连发合并、回复、投递回执、重启未知态和解绑止损。没有真实账号证据时保持默认关闭。

应用内与 IM 可以共享同一 owner 的获准长期记忆，但默认不共享历史、附件和出站目标。群聊使用独立 audience 和记忆范围，不能读取 owner 私人上下文。图片/文件在文本闭环稳定后接入统一 Artifact，不为每个渠道复制文件存储。

## 工程治理与验证

- 测试只保留关键契约：状态机/幂等、权限边界、持久迁移、来源引用、沙箱拒绝、真实启动烟测。UI 做模块语法检查和少数关键交互，不追求浏览器矩阵。
- 每次能力纵切合并一次验证与发布。Windows、linux/amd64 build/vet 仍必须都过；平台文件在目标平台检查。
- 新依赖必须解决明确能力缺口。标准库足够时不引入框架；PDF/OCR/Office、强制沙箱和媒体协议可采用成熟独立组件。
- API Key、设备令牌、IM 凭据和平台 Cookie 不进入日志、工具输出、模型上下文或同步包。
- 生产变更继续先备份数据与配置，再发布服务和同版本 APK；桌面发布加入同一版本证据，但本地数据不上传。

## 下一步完成信号

这些是方向上的依赖顺序，不是工期：

1. **桌面产品闭环**：一份可下载的 Windows 包打开即用，能配置模型、持续 loop、读写/分享获准工作区，并能安全升级和回退。
2. **本地任务闭环**：验证一种 Windows 强制隔离后，模型可编排多步命令；产物可下载，取消和重启后状态真实。
3. **显式跨端接续**：用户选择一个会话/产物在本地与云端之间交接，来源和受众不丢，失败不覆盖原数据。
4. **学习闭环**：从 PDF/PPTX 原页讲解、出题、作答、评分、错题复习到带引用导出，刷新和换端仍能恢复。
5. **真实 QQ 闭环**：owner 私聊可绑定、收发、重启恢复、解绑；应用消息不误发 QQ，群聊默认关闭。
6. **陪伴质量闭环**：真实回放样本显示换题、纠正、主动触达和语义分段改善；没有新意时能安静。

完成这些之前，不以新增插件数量、工具数量、设置项或侧栏入口作为进展指标。
