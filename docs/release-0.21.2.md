# 0.21.2 思考正文与模型默认输出预算

2026-11-06。服务端 0.21.2，Android 0.21.2-debug / versionCode 20。服务端和 Android 更新通道均已发布，沿用原包名、签名和设备身份。

## 行为

- 显示 ECNU 实际返回的 `reasoning_content`，逐段进入实时进度；思考中默认展开，完成后默认折叠，用户手动选择的展开状态在轮询重绘中保留。已有历史中保存过的思考也可查看。旧版本从未保存的思考不能补回。
- 思考正文按纯文本显示，独立于回答、复制回答、朗读和声明式组件；不执行 HTML、工具或写入，不作为用户授权、记忆候选或摘要来源。鉴权和会话归属保持，日志仍只写固定错误类别。
- 普通与开启思考的聊天默认不发送 `max_tokens` / `max_completion_tokens`，不再施加原 1024/4096 token 预算，由模型服务采用自身默认值与能力限制。`-max-output=0` 和 `POCKET_THINKING_MAX_OUTPUT=0` 表示省略参数；运维仍可显式设置正数。后台摘要、主动关怀和共同话题的原有独立小预算保留。
- 保留原有超时、工具轮数和网络/文件体积保护。上游主动截断时提示模型服务返回了截断，不再将其描述为项目设置的“本轮输出上限”；不会自动重试或补发。

## 持久化与回退

最终回答的思考正文沿用 transcript v2 的 `reasoning_content`。工具调用的思考继续按上游协议回传，普通最终回答的思考不额外发送进下一轮模型请求。

轮次台账有思考进度或超过旧 64 KiB 的回答时按需升级到 v3，保存 `reasoning_content`；可读取已有 v1/v2，不批量改旧数据。生成取消、失败和正常重启保留已收到的思考，重置清理该字段，删除仍按原会话/轮次归属。v3 的本次扩展并非 Harness 3B/3C 的持久结算实现。

保留 4 MiB SSE 传输保护、单条思考 256 KiB、每轮累计思考 1 MiB、回答 4 MiB、台账 12 MiB 等内存/存储保护；它们不是模型 token 预算。发生新 v3 写入后，不能只切回旧二进制，须保留新现场并使用兼容读取或显式转换，不能覆盖新数据还原旧备份。
