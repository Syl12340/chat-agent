# chat-agent 全面工程评估与实施规划

2026-11-23，源码基线 `5ea36df`，服务端源码版本 0.7.22，Android 默认 0.7.22-debug / versionCode 60。本文面向下一轮 DSH 实施，覆盖产品能力、工程缺口、架构取舍、依赖与完成标准。

## 结论

继续采用 Go Core、Web/PWA 和 Kotlin。电脑本地运行自己的 Core、工作区和持续 Agent loop，云端承担手机访问、常驻陪伴和 IM。四条活跃产品主线为仿生聊天与陪伴、DSH Harness 与双端 Agent、UI/GenUI 与课件学习、QQ 等 IM 联动。服务器小精灵、插件和 ComfyUI 为这些任务提供执行与产物能力。

当前已有相当完整的基础实现，主要工程缺口集中在能力之间的接线、提交后的状态核实和用户实际入口。建议先完成分页工具入口、完整模型路由、分类反馈以及本地启动恢复，再沿同一套任务与产物契约推进学习和 IM。实施按依赖组织，完成项合批验证发布，工期和发布批次由实际交付决定。

## 优先修正的工程问题

### 分页尚未接通工具 schema

`workspace_read` 的处理函数已能读取至 256 KiB，按 12 KiB 分页并返回完整文件 SHA-256、`next_offset`。注册时仍使用只有 `workspace` 和 `path` 的 schema，且声明 `additionalProperties=false`。执行器在调用处理函数前校验 schema，因此带 `offset` 的续读会得到 `INVALID_ARGUMENTS`。已有分页测试直接调用处理函数，覆盖不到这个入口。

先给读取工具独立声明 `offset`，校验字节范围及 UTF-8 起点。连续分页带版本约束，文件变化时返回冲突，避免模型把两个版本拼成一个文件。保留已有小文件输出兼容性。最小回归从注册后的 ToolExecutor 读取第二页，并覆盖一个跨 UTF-8 字符的页边界。[工具注册与读取](../plugins/builtin/workspace/plugin.go) · [执行器](../internal/probe/executor.go) · [现有测试](../plugins/builtin/workspace/plugin_test.go)

### 后台模型切换仍缺少完整路由

`fd3dda0` 让主动生成和手动摘要读取 `LastModel`，再调用 `selectChat`，目前仅复制 Model、BaseURL、APIKey。桌面从 demo 启动后仍可能带着 `Demo=true`，摘要也会优先使用启动时的 `UtilityModel`。选择失败被忽略，随后继续使用启动配置。`LastModel` 按台账倒序取非空模型，包含排队或取消的 turn，尚未定义“最后选择”和“最后执行”的产品语义。状态接口同样读取启动配置。

提取统一的按用途路由解析，明确会话默认、渠道默认、摘要默认和显式专用模型。一次请求固定模型、端点、凭据引用、demo 状态、能力、思考参数及超时。摘要默认跟随所选供应商，独立摘要路由应完整配置。被删除或不可用的显式选择返回可见错误。先让聊天、主动生成、手动与自动压缩接通，再按实际需要接语音和专用决策服务。

最小回归覆盖 demo 启动后配置真实模型、跨供应商摘要、删除当前路由三个场景，可用本地假 provider 观察请求，真实模型仅做必要的一次功能确认。[后台装配](../internal/api/knowledge.go) · [主动生成](../internal/api/proactive.go) · [台账选择](../internal/turns/store.go) · [摘要模型](../internal/probe/compaction.go)

### 分类反馈仍被全局间隔影响

`5ea36df` 新增按 EpisodeID 区分 greeting/followup 的 `CareKindMuted`，自动领取时会检查。`ClaimCare` 在此之前仍调用汇总所有类别的 `careInterval`，日常问候的负面反馈仍会拉长事件跟进的间隔。`careMotivation` 也继续汇总所有类别。当前“less”在达到一半评价后会阻断整类自动触发，持续时间受 30 天窗口影响，与逐步降频存在体验差距。

让间隔、采样、动机上下文和用户解释使用一致的类别范围。全局暂停、安静时段和总额度继续作为显式全局约束。“少一点”采用有界降频，“暂停此类”才进入暂停状态，并提供恢复入口。旧无 EpisodeID 记录需要兼容规则，避免将未知来源直接当成新的偏好证据。

最小回归直接走 `ClaimCare`，构造同一角色近期问候收到 less、事件到期的场景，确认跟进只受明确的全局预算约束。分类 helper 的测试可继续保留。[领取与间隔](../internal/companion/life.go) · [动机上下文](../internal/api/life.go)

### 启动恢复需要进程所有权

默认 Documents 缺失时工作区回退到用户目录，而默认数据目录通常位于用户目录内，触发工作区与数据目录互斥检查。memory、runtime registry 等使用独占创建的锁文件，硬退出可能留下锁。部署脚本等待进程最多十秒后仍会广泛删除 `.lock`，没有在超时后确认所有权就终止清理。

首次启动创建独立工作区并记住用户选择。统一实例锁的所有权与恢复逻辑，优先采用进程退出自动释放的 OS 锁，已有锁格式保持兼容。重复启动复用已有实例，异常退出恢复历史并标明未结算操作。部署清理仅针对已证明失效的应用锁，停止失败时中止发布。最小验收覆盖无 Documents、重复打开、强制退出后重启和仍有活跃实例四种情况。[桌面默认目录](../cmd/server/main.go) · [memory 锁](../internal/memory/store.go) · [registry 锁](../internal/runlog/registry.go) · [部署脚本](../deploy/install.sh)

### 文件写入需要冲突协调与业务回执

工作区写入执行 hash 检查、临时文件、Sync 和 rename。同一路径缺少跨会话串行化，两个调用可能通过同一旧 hash。`missing` 的检查与创建也存在窗口。旧内容通过 Stat 后使用 `ReadFile`，文件并发增长时仍可能超出先前大小判断。工具运行记录已有 operation，但该写入尚无可独立核实的持久业务回执。

宿主内按工作区和路径协调写入，使用句柄级有界读取，提交前重新核对版本，创建时要求目标仍不存在。回执关联 operation、参数摘要、旧/新 hash、目标和提交状态。重启后先核实真实文件，提交状态不明时保留 unknown。外部编辑器不受宿主锁控制，支持的并发保证需在接口语义中说清。

最小回归覆盖两个请求写同一旧版本最多成功一个、创建冲突、提交后回执前退出的恢复。先复用 runlog 和 pluginapi 的回执能力，再决定是否需要额外文件提交日志。[工作区写入](../plugins/builtin/workspace/plugin.go) · [业务回执](../internal/pluginapi/plugin.go) · [运行结算](../internal/runlog/runlog.go)

### 隧道修复已推进到可维护性阶段

`c7547e6` 已增加带令牌探针、20 秒 HTTP 超时，区分 200/401/503，移除了按监听端口杀进程，并逐段守护复用的组件。后续重点为网页和本地桥的应用级探针、SSH 建连时限、探针失败的退避与恢复判定。当前本地检测仍只检查监听端口，`-Check` 总是返回 0，自动化无法据此识别断线。

赋予检查明确的机器可读结果与退出码，保留桥可达但生成未就绪的状态。注册登录守护前完成重复启动、桥后端离线、网页单段断开恢复的轻量验收。登录计划任务需要用户决定系统配置。[隧道脚本](../scripts/tunnel.ps1)

## Linux 服务器沙盒专项

2026-11-25 只读核对生产 `0.7.22`，内核 `6.8.0-55-generic` / x86_64，Landlock ABI 4。运行中的服务已加载 `workspace_shell`、工作区读写及文件分享，服务账号为 `chat-agent`，`NoNewPrivileges=yes`，授权会话计数为 0。此处验证到工具注册和授权状态，实际执行仍以受控工作区任务验收为准。[授权状态接口](../internal/api/host_tools_http.go)

未授权的云端会话在组装工具时会过滤 `workspace_*`，仍可能收到绑定电脑用的 `local_workspace` 等工具。现版由管理员在目标会话打开「连接信息 → 服务器运维」并保存授权，下一轮使用服务器沙盒。把「服务器沙盒已配置，当前会话待授权」显示在会话内的工具入口，可让用户直接判断可用性。现有流程见[部署说明](../deploy/README.md#可选的工作区与主机巡检)。

模型可以通过 `workspace_shell` 编排 `/bin/sh` 命令。`read-only` 允许读取工作区，`workspace-write` 允许在工作区写入，两者都有每次调用的临时目录。当前执行器应用 Landlock 文件规则、seccomp 套接字过滤和进程资源限制，执行器配置超时为 12 秒。无法安装所需隔离时返回 `SANDBOX_UNAVAILABLE`。已配置的固定动作 `workspace_exec` 使用另一条执行路径。[工具定义](../plugins/builtin/workspace/plugin.go) · [Linux 执行器](../plugins/builtin/workspace/exec_linux.go)

| 依赖顺序 | 实施工作 | 交付判据 |
| --- | --- | --- |
| 会话授权与隔离探针 | 将工作区使用权与 `server_action` 等维护权限分别授权，界面沿用现有会话设置。宿主按实际命令、工作区和模式判定，写入型 shell 使用已有一次性批准票据。就绪状态检查实际隔离策略能否在服务环境安装，准确区分不可用、未授权与执行失败 | 仅授权工作区的会话看见沙盒工具，撤销后无法发起新任务。已批准参数变化需要重新授权。隔离不可用时 shell 被拒绝 |
| 每任务资源与执行状态 | 沿用非 root 进程级方案，把执行放入独立资源组，优先复用 systemd/cgroup 能力。为任务设置进程数、内存、CPU、总时长与输出上限，收敛运行身份和文件描述符。临时目录写权限与最终子进程的 `TMPDIR` 保持一致 | 任务到达上限或取消后，所有任务进程退出，聊天健康正常。回执显示退出结果、耗时、输出截断和取消终态 |
| 多步任务与文件交付 | Harness 编排短命令，长作业使用独立 operation，Web/Android 从同一工具卡观察状态。小文件继续沿用 `workspace_share` 的鉴权下载，需要跨重启保留的结果保存为不可变产物，并关联会话、操作和 SHA-256。中断后查询原 operation | 用户能完成“读取样例 → 运行 → 下载成果”。过期或撤权后的文件明确拒绝，重启后能核实原任务的状态和可用产物 |

当前 `workspace` 与服务器运维共用会话授权，shell 标记为高风险且必须走独立判断，但没有声明 `ApprovalRequired`，与 `workspace_write` 的逐次人工批准不同。生产 `TasksMax=128` 和 `MemoryMax=256 MiB` 是聊天服务与子进程共享的上限，独立的任务资源组应先用于隔离任务负载与聊天服务。复用按文件规则时保留最小描述符继承范围。 [会话准入](../internal/api/host_tools.go) · [批准逻辑](../internal/probe/decision_gate.go) · [Linux Landlock](https://docs.kernel.org/userspace-api/landlock.html#kernel-interface) · [systemd 资源控制](https://www.freedesktop.org/software/systemd/man/latest/systemd.resource-control.html)

现有持久工作区先在获准会话和专用样例目录验收。验证只读检查、经批准写入与下载，同一任务内验证越界写入和联网被拒，再执行一次有界取消并核对终态。面向日常对话的临时任务使用单独工作区，按下文的权限交互设计接入。工作区任务和受限服务器维护分别记录操作回执。

## 四条产品主线的深化

### 仿生聊天与主动陪伴

先完成上述反馈链路，再推进运行中补充。输入在下一模型 step 被接纳时持久记录接纳回执，其他输入进入下一轮队列。同来源、发送者和受众校验沿用现有 Envelope，补充对已批准工具的参数修改需要新的授权。提示词描述当前真正可用的工具，模型自行选择表达、分段与沉默。

记忆操作放在相关消息旁，支持查看来源、提议记住、纠正和遗忘。审核结果与检索上下文同步，避免旧摘要重新引入已纠正内容。用少量连发、换题、纠正、结束话题和主动回复样本检查漏答、重复追问、错误召回及打扰，样本以脱敏或合成内容为主。

完成标准是用户能自然补充和换题，获准信息能跨私人会话接续，少一点只影响对应触达，主动消息能说明来源，允许安静。

### DSH Harness 与双端 Agent

普通 turn 已采用工具驱动的持续 loop，默认 MaxTurns/MaxToolCalls 为零，默认总超时仍为五分钟。长任务应以独立 operation 生命周期承载，提供有限日志、进度、取消请求和实际终态，重启后核实已提交副作用。

电脑文件任务完成后，推进一种可执行、可验证的 Windows SandboxBackend。Linux 继续使用现有 Landlock 路径，固定动作和自由 shell 的约束分别公开。模型可以编排命令，授权绑定脚本或参数、工作区、网络范围和期限。跨端接续从用户选择的一段会话或一个产物开始，保留来源与权限，导入历史操作只读。

桌面发布先提供稳定下载入口、版本清单和完整性验证，再做安装更新、真实性校验、切换失败回退和数据格式兼容。完成标准是本地打开、配置模型、连续执行、交付成果，并能在中断后明确查询真实结果。

### UI GenUI 与课件学习

资料链路按原件与不可变版本、提取作业、页图与 SourceRef、学习动作、成果导出推进。当前课件只保存提取文本与索引，PDF 分支明确拒绝。先持久保存原件，再支持有文本层的 PDF 和 PPTX 原页，之后增加 OCR、图片与公式区域。旧资料显示原件缺失状态，补传时核对原 hash。[课件存储](../internal/courseware/store.go)

现有 quiz 会将结构化答案写入聊天 turn，UI 能从消息恢复答案，持久学习 surface 也已存在。下一步增加独立题目版本、作答、评分和错题记录，让刷新、换端和复习使用稳定业务身份。GenUI 从这些记录呈现视图，答案提交使用 revision 与幂等键，评分可保留方法及模型版本。[答题恢复](../web/ui/render.js) · [学习面板](../internal/api/study_surfaces.go)

会话保持主入口。资料原页、任务、文件、图像和学习成果按需打开工作台，手机使用抽屉或详情页。设置集中在连接、模型和偏好，工具参数和日志进入展开区。当前 app.js 约 83 KB、style.css 约 73 KB，14 份样式表含组件样式与覆盖层。随上述功能拆分会话状态、设置和工作台模块，给样式确定归属并清理被替代规则。页面是否好用需要实际交互验证，文件数量仅用于定位维护成本。

完成标准是上传课件、打开回答引用的原页、讲解、答题、评分、复习及带来源导出在同一体验中成立。

### QQ 等 IM 联动

沿用 AstrBot 收发网关和 CA 的身份、记忆、工具与结算。先完成真实 owner 私聊的绑定、连发、去重、回复、重启未知态与解绑。当前适配器把多气泡逐条发送后统一回执，需要明确部分送达的语义。某个气泡已送出而后续失败时，应保留进度或 unknown，避免整批盲目重发。[AstrBot 适配器](../integrations/astrbot-chat-agent/main.py)

随后用统一 artifact 接图片与文件，发送前核对目标受众、所有权、体积、MIME 和有效期。应用与 QQ 可共享已获准 owner 记忆，消息历史、附件和发送目的地分别授权。群聊具备独立 audience，开放前验证记忆、摘要、工具和产物的私人隔离。Telegram、飞书、企微维持用户确定的暂缓状态。

完成标准是实际 QQ 平台的一条输入只有一次 CA 结算，有可信送达记录，应用消息去向明确，解绑后停止领取回复。账号缺席时保留待实测项，其他能力照常交付。

## 权限交互与授权模型

当前的服务器沙盒体验暴露了三处不一致。对话缺授权时，注册的工作区工具会被过滤，界面把操作藏在管理员的「连接信息 → 服务器运维」里。该开关同时放行工作区与已配置的运维工具。运行中，`workspace_write` 和 `server_action` 明确要求人工批准，`workspace_shell` 只声明独立风险判断要求。签发批准票据后，界面还要求用户再发一条消息让模型复述调用参数。[会话能力准入](../internal/api/host_tools.go) · [操作签发](../internal/api/approval.go) · [现有确认界面](../web/app.js)

产品上只解释三个问题：**这台设备能否进入 CA、Agent 这次在哪个工作区工作、这个动作会改动什么。** 设备 challenge、插件授权、沙盒策略、短期凭据和决策服务仍由宿主管理。已登记设备继续无感进入，运维和绑定电脑入口按实际需求出现。风险判断用于辅助决策，敏感动作是否需要用户确认由宿主策略确定。

### 从一句任务指令开始

用户在手机上传 CSV 并说“用服务器沙盒统计一下”，CA 在已验证的隔离执行环境内创建临时工作区，只放入本次资料。卡片显示「服务器沙盒 · 读取 1 个附件 · 生成报告」。检查、计算和把结果还给同一会话可随任务连续完成。用户指定服务器上的持久目录、要求改原件或把报告发送到 QQ 时，工作台显示具体目标，必要的确认在原对话里完成。用户点击后，宿主继续执行先前记录的同一调用，反馈操作结果。

工具未配置、沙盒隔离不可用、当前任务待授权、绑定电脑离线是不同的事实。宿主应提供不含密钥、目录信息或设备标识的状态摘要，Web/Android 与模型使用同一来源。只有可执行的工具进入当前工具集。需要授权时，宿主根据已验证的目标和操作生成可点击卡片，模型可以提出请求。后台触发和 IM 不继承应用私聊的工作区授权。

### 实施与兼容

1. 在现有 API 与工具装配层统一计算是否可用及原因，先用于服务器沙盒与对话工具卡。区分登录设备、远程执行端和执行位置。客户端由上下文展示最短操作路径，保持设置页只管理设备与已授资源。
2. 利用已有 `hostGrants` 与插件策略做窄范围授权。将任务临时目录、指定持久工作区、服务器维护，以及远程电脑访问视作不同资源。租约只覆盖已说明的工作区、读写范围和期限。先增加临时任务路径，旧持久工作区保持显式授权。旧会话开关的兼容按原资源范围过渡，新增临时沙盒权限不继承主机维护权限。
3. 复用一次性批准，补齐请求主体、受众、待确认操作 ID 和有效权限版本，与规范化参数一同校验。消费票据前重新检查真实授权，宿主推进同一 operation，重复点击可以查到已执行状态。撤销后新的工具调用与未开始的作业必须停止准入，已运行任务按取消语义报告真实状态。

最小验收用一个已登记手机账户和一个既有云端私聊。发送同一份样例文件，验证可直接启动临时任务、下载结果，随后验证持久目录写入需要确认、确认后自动继续且重复点按只执行一次。最后撤销工作区授权并验证未开始的任务受阻，维护和 QQ 仍按各自权限运行。

## 私有实例与任务沙盒

每位使用者拥有一套独立 CA 实例，进入自己的实例就是它的 owner。一个人也可以选用多套彼此隔离的实例，例如日常使用与试验。借鉴虚拟环境的独立配置，以及 Hyper-V 的独立启动、停止、升级和回滚操作。多实例部署复用同一份单 owner Go Core。

| 层级 | 谁管理 | 独立的边界 |
| --- | --- | --- |
| 宿主 | 服务器管理员 | 分配服务身份、入口、磁盘和资源配额，创建、迁移和维护实例。宿主级运维留在此范围 |
| CA 实例 | 实例 owner | 独立的服务进程、设备白名单、签名身份、凭据、模型配置、数据、长期工作区、渠道和后台调度。每个实例可停启、备份、恢复和选择发布版本 |
| 任务沙盒 | 实例内的 Agent 按用户授权使用 | 按任务挂载所需输入和结果目录，限制网络与资源，关联执行回执。任务结束回收临时目录，获准产物保留在实例内 |

CPU、内存、进程数与磁盘分别配置实例上限，共用推理或 ComfyUI 时由宿主调度队列与份额。服务账号、文件所有权、网络入口和每任务的隔离都需要生效，单靠分目录无法提供此边界。进程级方案共享 Linux 内核，适合受控用户、受信 Core 和默认受限的任务。对互不信任的使用者开放任意命令或插件前，选定独立 VM 或 microVM 等隔离方案并验证。[systemd 资源控制](https://www.freedesktop.org/software/systemd/man/latest/systemd.resource-control.html)

### 最小实施

1. 先参数化部署。现有 `cmd/server/main.go` 已支持 `-listen`、`-data`、工作区配置和独立服务器签名密钥。`deploy/start.sh` 和安装脚本仍固定单服务账号、数据路径和监听端口。用 `chat-agent@实例名.service` 启动两套进程，给每个 unit 分配不同的非 root UID、配置、数据目录、工作区、监听入口和发布指针。同一发布二进制可以只读复用。[Core 启动](../cmd/server/main.go) · [启动脚本](../deploy/start.sh) · [systemd 模板服务](https://www.freedesktop.org/software/systemd/man/latest/systemd.unit.html)
2. 实例由宿主或受控创建入口分配。首次启动签发只适用于该实例的一次性认领凭证，完成第一台设备登记后继续采用现有无感 challenge。每台设备通过独立私钥证明公钥指纹，同一账户的信任设备等效，可以管理信任列表并共享实例资源。Web 使用不同 origin，Android 以实例入口区分凭据和偏好。配置、备份和释放资源都以实例为单位。
3. 默认只允许 Agent 在实例内的任务目录处理本次输入。管理实例内模型、设备和文件属于 owner 权限，触及宿主维护、跨实例共享或对外发送时由实际资源和目的地重新授权。复用现有任务回执和文件下载。新增实例不复制现有实例的认证材料或历史数据。

首个验收用 A 和 B 两套干净实例。分别登记同一台手机，创建同名会话、文件和任务，确认各自只看到本实例的数据。A 的凭据、附件链接和任务 ID 在 B 上无法访问。停止、升级或恢复 A 时 B 继续处理对话。A 的任务触及其资源上限后 B 仍可工作。验证完成后再考虑开通自助创建或将现有生产实例迁移为默认实例。

## 共用架构与上游复用
