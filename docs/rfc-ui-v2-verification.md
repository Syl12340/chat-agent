# RFC：Generative UI v2 最小验证方案

## 2026-11-09 修订决议（优先于下方初稿）

配合[本体方案](core-plan-2026-11.md)的 B/C 阶段。复用现有组件测试，将下方六场景合并为三个关键流程：创建/更新/刷新重开及第二客户端；旧 revision/无效来源在入队与执行前拒绝；删除与迁移故障恢复。增加唯一必要的边界：消息已提交但 surface 发布前中断不能产生半个 UI 状态。

迁移测试以现有 runtime v2、history v1/v2、turns v3 为输入；新格式由实施时冻结，不能测试尚不存在的 `migrate --to 2` 命令。普通摘要不改变 ID，但仍按 floor 拒绝旧操作；追加消息不应让已有引用失效。

浏览器仅在已知 revision 过期时提前禁用按钮；服务端始终负责权威拒绝。竞态下客户端尚不知道过期、请求已发出是正常情况，应收到冲突且不执行动作，不能以“绝不发请求”为通过条件。

纠正文末失败处理：本地测试失败修复临时数据上的实现即可，不能因此回退生产。迁移校验失败不切换权威代；只有实际发布失败才按当次回退方案处理。删除 update 来源时 surface 冻结，revision 不回退；删除 create 来源时整体失效。

## 初稿（涉及上述决策的条目已被修订）

状态：草案。配套 `rfc-message-identity.md`、`rfc-generative-ui-v2.md`、`rfc-ui-v1v2-compatibility.md`。

原则：**六个场景、本地临时 Provider、不调用真实模型、不发真实 QQ、不做完整矩阵。**
符合 AGENTS.md「只保留关键行为的最小测试」。

## 1. 六类关键场景

| # | 场景 | 通过标准 |
| --- | --- | --- |
| S1 | 创建 | surface 落盘，刷新后仍在原位 |
| S2 | 更新 | revision 递增，界面原地替换，不产生第二个界面 |
| S3 | 过期 | 旧 revision 的操作被拒绝，UI 转为只读 |
| S4 | 删除 | 消息/turn 删除后 surface 不残留、不报错 |
| S5 | 刷新恢复 | 重新加载后由日志重建，按钮状态正确 |
| S6 | 跨设备打开 | 第二个客户端看到同一 revision 与同一只读状态 |

## 2. Go 侧测试（`internal/api`、`internal/probe`）

沿用现有 fixture 风格：`httptest` 模拟 SSE，临时目录做数据。

### S1–S2 创建与更新

```
Given 一个会话与一条已完成的 assistant 消息
When  日志写入 surface create（revision=1）
Then  回放后投影到 1 个 surface，lifecycle=active
When  追加 update（revision=2，内容替换）
Then  投影仍为 1 个 surface，revision=2，内容为新内容
```

断言要点：**surface 数量恒为 1**（不是每次更新多一个）。

### S3 过期拒绝

```
When  用 revision=1 提交操作，而当前为 2
Then  返回 409 + 当前 revision；不产生任何写入
```

同时覆盖 Message Identity 层：拿已被 compact 折叠的消息 ID 提交，必须被拒绝。

### S4 删除

```
When  删除包含 surface create 的那一轮
Then  该消息 ID 进入 tombstone；重建后该 surface 消失，不抛错
      后续对该 surface 的 update 被拒绝（理由：来源已删除）
```

### S5 刷新恢复（服务端部分）

```
When  关闭并重新打开会话（新进程 / 新 Session 实例）
Then  投影与关闭前一致，revision 不回退
```

## 3. 前端测试（Playwright，本地演示模式）

用现有 `-demo` 服务，不接真实模型。

| 步骤 | 断言 |
| --- | --- |
| 打开含 surface 的会话 | 卡片出现在正确消息之后 |
| 刷新页面 | 卡片仍在、revision 显示不变 |
| 点击旧 revision 的按钮 | 请求不发往 `/turns`，UI 提示已过期 |
| 拖动 sine 滑块 | **网络面板无请求**（本地交互零模型调用） |
| 两份 context 指向同一会话 | 两边看到的 revision 一致 |
| 删除该轮后再看 | 卡片消失、无控制台错误 |

`web/ui/state.js` 的缓存清空行为要单独确认：切换角色/会话后重进，
界面必须由服务端重建，而不是靠内存残留。

## 4. 迁移验证

在临时目录放三份样本：

1. 纯 v1 旧文件（无 `id`）
2. 混合文件（部分消息有 `id`）
3. 损坏文件（截断的最后一行）

期望：

- (1)(2) `migrate --dry-run` 报告数量正确，正式迁移后能打开；
- (3) 迁移**中止**并指出行号，不产生半个文件；
- 同一文件多次 dry-run 结果一致（派生 ID 幂等）。

## 5. 明确不做的验证

- 不做真实模型表达质量评估（属 0.27.x 稳定性收口，另行少量场景）。
- 不发真实 QQ / OneBot 消息。
- 不做全组件 × 全状态矩阵；只跑上面六个场景。
- 不做第二模型复核。

## 6. 完成定义

六项全部通过，且回归清单（见兼容方案第 6 节）全绿，才认为 v2 可进入下一阶段。

任何一项失败：**回退到备份，不在半迁移状态上继续开发**。
