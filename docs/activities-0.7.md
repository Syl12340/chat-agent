# chat-agent 0.7：共同活动

后续更新：0.8.0 已支持在关联活动的聊天中明确要求保存进展、暂停/恢复/结束，活动类型不再固定交流策略；见[当前说明](natural-activities-0.8.md)。以下保留 0.7 的交付记录。

2026-11-03，文字共同活动已实现。沿用 Go 标准库、原生 JavaScript 和现有 Kotlin 客户端，无新增第三方依赖。

## 使用

侧栏打开“共同活动”，选择一种方式：

| 活动 | 交流方式 |
| --- | --- |
| 睡前聊一会儿 | 轻松、简短，允许自然结束，不催促继续聊 |
| 一天里的一件小事 | 从一个日常片段聊起，不强制总结或给建议 |
| 共同兴趣 | 围绕兴趣和上次保存的位置继续，事实需要时再搜索 |
| 小目标陪伴 | 一起找用户愿意做的一小步，可以休息或换方向 |

填写名称和想做的事，点击“创建并打开聊天”。应用会建立活动记录、关联一个新会话，并将开场放进输入框；**点击发送后才调用模型**。当前输入框已有草稿时会保留它，先发送或清空，再从活动列表“接着聊”。

聊天中的活动横条可以打开管理面板。在“编辑进展”里手动保存愿意留到下次的内容，之后从活动列表“接着聊”会创建关联同一活动的新会话，并使用保存的进展。不会自动把聊天原文提炼成长期画像，也不把活动进展自动转为待办或提醒。

支持暂停、结束、恢复并接着聊、编辑目标、清空进展和删除。暂停/结束后不再注入活动资料；恢复由用户明确点击。普通新会话没有活动上下文，不会因为同一角色还有活动就强制接续。角色之间保持隔离。没有分数、连续签到或关系等级。

## 保存和边界

- 活动独立存于 `<data>/activities/state.json`，版本化 JSON、独占实例锁、同步后替换；不修改旧 JSONL 或事件/关怀文件。
- 每角色最多 50 项、全部角色最多 200 项活动；名称 256 字节、目标 2048 字节、进展 4096 字节。最多 2048 个创建去重标识、4096 个会话绑定，文件上限 4 MiB。
- 创建先保留请求标识。不确定提交只提供查询和同标识显式确认，不自动 POST；删除后也不允许旧请求重新创建记录。修改校验 revision，旧页面不能覆盖新版本。
- 修改活动资料、暂停、结束或删除时，保存关联会话的上下文起点，后续模型跳过此前聊天/摘要，防止旧进展覆盖新内容。原始聊天仍可查看，这也会使这些会话的其他旧背景暂时不再用于模型。模型正在生成时需先停止，再修改活动。
- 清空当前聊天保留活动与保存进展；活动删除不同时擦除原始聊天、已导出文件或备份。保留少量去重摘要与绑定元数据，防止旧请求复活，并维持上下文起点。
- 页面关闭不自动保存尚未提交的编辑；当前页面会保留编辑草稿，退出登录清除私有临时内容。不确定创建保存在当前站点的 sessionStorage，不存访问令牌。
- 当前版本只有文字共同活动；语音、系统推送与第三方 IM 仍未加入。活动本身没有后台轮询、自动关怀或自动模型调用，原有关怀开关独立管理。

## 最小验证

新增一条 `TestSharedActivityLifecycle` 集成测试，覆盖创建去重、绑定上下文、保存/纠正进展、暂停/结束、跨会话恢复、角色隔离、删除重启与会话重置。另运行六项相关已有检查，覆盖聊天、角色记忆、陪伴偏好、持久队列、事件关怀和摘要；均使用本机虚构端点，不消耗真实模型额度。

前端通过一条无网络模拟流程，覆盖创建、编辑、恢复、未知请求同标识确认、草稿、角色切换旧响应保护和退出清理。Android API 35 模拟器验证四模板、明确发送、保存进展、跨会话继续、刷新、暂停/恢复/结束/删除，以及普通会话和角色隔离。

服务器单独数据目录使用一轮 ecnu-max 对话验证：新关联会话正确接上保存的《三体》阅读进展；随后暂停活动。生产聊天、用户活动和偏好不用于该收费验收。
