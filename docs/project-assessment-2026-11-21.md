# 当前项目评估与实施方向

评估日期：2026-11-21。源码基线：`a50e9fd`（0.7.19），检查开始时工作区干净。本文依据本地源码、现有测试内容和发布记录，未再次调用模型、登录 QQ、巡检生产或运行测试。上线状态引用 [0.7.19 发布记录](release-0.7.19.md)，不作为本次新的线上验收。本次只调整文档。

## 1. 结论

CA 已经有可继续发展的 Go 核心：持续工具循环、持久会话与运行记录、审批、记忆、Web/Android 界面、工作区、声明式面板和 IM 网关均有实现。当前重点是把这些能力接成用户真正能完成的任务，并修正能力说明与代码的差距。

继续采用 Go Core + Web/PWA + Kotlin。电脑本地端直接运行自己的 Core 和 loop，无需绑定；云端承担手机、常驻陪伴及 IM。使用远程模型仍需网络，“本地 loop”不意味着模型推理也离线。

下一步先处理本地启动、模型路由、文件读改三条基本链路，再沿四条产品主线推进。桌面自动更新、完整跨端同步、通用插件市场都不应阻塞这些链路。

## 3. 本次发现的具体缺口

以下是源码可确认的路径或条件性问题，没有把它们描述成已发生的生产故障。

### A. 读取结果与写入前置条件未接通

`plugins/builtin/workspace/plugin.go` 的 `read()` 只返回正文，`write()` 却要求旧文件的精确 SHA-256。读取上限是 12 KiB，写入上限是 256 KiB，部分可写文件也无法通过当前读取工具完整复查。已有写入测试在测试代码里计算 hash，未覆盖模型通过工具结果拿到 hash 的流程。

应让读取结果返回路径、编码、字节数、内容、完整文件 hash、是否截断及读取范围。大文件支持分页，写入依据完整文件版本，不能拿片段 hash 当整个文件 hash。无需让用户复制 hash，也不应迫使模型先发布下载附件才能得到它。

### B. 原子替换没有覆盖并发编辑与提交恢复

当前 `write()` 在检查 hash 后执行临时文件写入和 rename，缺少同一路径的写入串行化；`missing` 检查与最终替换之间也有窗口。多个会话可以同时通过旧 hash 检查。rename 避免半个文件落盘，但不保证没有覆盖并发修改。

另有两个边界：旧文件通过 Stat 后仍用无读取上限的 `ReadFile`，文件并发增长时不再受初始大小检查约束；文件写入没有与结果一起持久化的专用业务回执，提交后进程退出时不能仅凭回复判断是否已经写入。

应复用工作区写入能力：宿主内按路径协调、句柄级有界读取、提交前复查、创建时拒绝替换已存在目标、提交记录关联 operation。外部编辑器不受宿主锁约束，必须明确支持的并发保证；不宣称普通 rename 是文件系统 CAS。结果不确定时读取实际 hash 核实，不能直接重写。

### C. 默认桌面目录与恢复仍有启动缺口

`cmd/server/main.go` 的 `defaultDesktopWorkspace()` 在 `Documents` 不存在时回退到用户目录；`defaultDesktopData()` 通常位于该目录下面。工作区构造函数禁止与数据目录相互包含，因此这一默认路径组合会被拒绝。

同时，`internal/memory/store.go` 使用独占创建的 `.store.lock`，正常关闭才移除；桌面进程被强制结束后的恢复不能依赖用户手动删锁。

应默认创建独立、不会包含数据目录的工作区，提供一次选择并记住路径；已有实例复用窗口；异常退出通过可验证的进程所有权/OS 锁处理。只清理能够证明失效的锁，不能为了启动忽略存活实例。

### D. 模型配置只完整接通了普通聊天路径

`internal/api/turns.go` 为普通 turn 替换模型、端点、密钥和 Demo 标志；`runProactive()` 与手动 compact 使用基础 Agent 配置。桌面无环境配置启动为 demo 后，即使对话选择动态真实模型，主动关怀或手动摘要仍可能沿用 demo。`/api/status` 与网页 demo 提示同样读启动配置，可能与当前对话路由不一致。

摘要还有另一条件性缺口：`UtilityModel` 在启动时选择，动态聊天路由未同步更新它。若启动模型为 ECNU、对话后来换到另一供应商，自动压缩可能把 ECNU 的摘要模型名称发给新供应商端点。

应统一 `ResolveModel(purpose, session)`：聊天、摘要、主动关怀、决策、语音分别有清楚的选择规则，解析后一次请求持有完整路由快照。默认摘要跟随当前聊天供应商，专用模型必须显式配置；后台任务缺少真实模型时显示未配置。决策模型有独立协议，不能直接拿普通聊天模型冒充。界面分别显示当前运行位置、当前模型与服务能力。

### E. “少一点”目前是整体降频

`internal/companion/life.go` 的 `careInterval()` 聚合角色近 30 天所有反馈；`internal/api/life.go` 的 `careMotivation()` 也聚合整体计数。当前实现没有按主题或触发类别筛选，因此“少一点这种”的体验尚未成立。

应先区分已获准事件跟进和可选日常问候，再按可信事件/主题标识积累有界反馈。全局暂停仍独立存在；旧反馈作为未分类信号，不猜测它属于哪个主题。先修正说明与行为的一致性，再用少量真实样本调整措辞。

### F. 课件原件没有保存

`internal/courseware/store.go` 的 `Add()` 对上传原文算 hash，但只落盘提取文本和索引，PDF 分支明确拒绝。现有 SourceRef 能定位提取文本与 PPTX 幻灯片标记，不能据此还原上传的幻灯片图片、公式或原始排版。

学业方向应先持久保存原件与不可变版本，再增加提取文本、页图、定位映射。旧资料若仅有提取文本，要标为 `original_missing` 并支持重新上传核对 hash，不能伪造原件可用。

### G. 插件和 UI 的扩展程度应按实现描述

`internal/pluginapi/plugin.go` 的 Registry 实际提供 Tool 与 Service；工具附属 Prompt 不等于独立 Prompt/Context 插件接口。`web/index.html` 同时加载 14 份样式表，其中既有组件样式也有历史覆盖层；文件数量本身不是缺陷，但全局页面与覆盖规则需要有明确归属。

按当前需要先做模型路由服务、上下文来源和触发器扩展，逐一验证可停用与降级。UI 随功能抽取导航、设置、对话与工作台边界，逐步去掉被替代的 CSS；避免集中换框架或新增总控管理页。

## 4. 下一步方向与依赖

### 基础链路：优先完成

| 工作项 | 要改的核心行为 | 最小完成场景 |
| --- | --- | --- |
| 本地启动与恢复 | 独立默认工作区、记住选择、实例/锁恢复、明确模型就绪状态 | 没有 Documents 也能打开；异常退出后重启保留历史；无需绑定 |
| 模型路由统一 | 按用途解析完整路由；模型能力、默认项、摘要和后台消费者一致 | UI 新增模型后正常对话、摘要和已启用关怀都按选定规则工作；更换供应商不借用旧模型名 |
| 读改文件闭环 | 带版本读取、分页、协调写入、结果核实、下载交付 | “读这个文件→改一处→复查→给我文件”完成；并发修改可见，未确认提交不重复写 |

已有源码能支撑的短链路优先补齐。桌面发布先提供稳定名称的可下载包与完整性清单，自动更新与安装器随后跟进；正式签名的清单和原子切换不能只靠同源 SHA-256 替代真实性校验。

### 主线一：仿生聊天与主动陪伴

1. 反馈分范围：区分问候/事件跟进，关联来源、保留时间和频率作用，避免一次反馈降低所有有价值的关怀。
2. 运行中补充：同来源、同受众的补充在下一模型 step 接纳，并记录“本轮已接纳”；其他输入排下一轮。补充不能追溯修改已批准工具的参数。
3. 记忆纠正：相关消息旁提供候选审核、纠正/遗忘结果；设置只保留集中查看入口。
4. 表达质量：选连发、换题、纠正、结束话题和主动回复等少量样本回放，关注漏答、重复追问和过度建议。继续由模型决定表达，不引入显式模式切换或前置分类模型。

完成表现：用户补充能被接住，换题不被旧目标拉回，“少一点”影响对应触达，主动消息有来源且允许沉默。样本不未经同意进入仓库或外部模型。

### 主线二：DSH Harness / 本地任务

1. 桌面和云端共用 Core；装配层决定工作区、认证、模型、触发和执行能力。旧远程执行端是可选能力。
2. 在读写闭环上增加 SandboxBackend，先验证一种实际可用的 Windows 隔离方案，再注册自由 shell。工作目录限制和进程超时不能替代文件、网络、子进程等强制约束。
3. 长任务通过 operation 展示进度、有限日志、取消请求与真实终态；现有五分钟总时限不等于无限后台执行，长任务需要独立生命周期。
4. 跨端接续先做用户选择的会话/产物交接，再评估持续同步。凭据不进入包，权限不随导入自动扩展，历史任务不重放。

完成表现：本地打开→选择工作区→模型连续执行→查看变更/产物→中断后查询真实结果。手机调用远端电脑不是完成此场景的前置条件。

### 主线三：UI / GenUI / EduWork

顺序为：**原件与版本 → 提取作业 → 页级 SourceRef → 学习动作/记录 → 多种视图**。

先支持有文本层的 PDF 与 PPTX 原页，再按需要接入扫描 OCR、图片和公式。资料解析复用 operation；原件、文本、页图、成果作为不同 artifact。试题、作答、评分、错题记录具有独立 ID 和 revision，GenUI 只投影这些记录；点按钮提交业务动作，普通“继续讲解”可写入草稿。

布局保持会话为中心：资料预览、任务和成果按需展开工作台，设置集中放连接/模型/偏好；减少侧栏常驻入口。保持声明式组件、公式、表格、图形与旧消息降级显示，业务完成不依赖从聊天文本反解析状态。

完成表现：上传课件→打开原页→讲解→做一道题→获得评分/解析→复习→下载带来源成果；刷新后仍保留真实作答。

### 主线四：QQ / IM

先使用现有 AstrBot transport 网关完成 owner 私聊文本接入：绑定、连发、一次结算、实际送达、任一侧重启、unknown 与解绑。真实实例和账号是这一项的外部条件，账号未就绪时其他主线照常推进。

随后用统一 artifact 增加图片/文件，复用来源和受众校验。应用与 QQ 共享获准长期记忆，聊天历史与出站目的地各自明确。群聊和其他平台在私人隔离验证后按需增加；TG/飞书/企微继续暂缓。

## 5. 架构改造随用户能力推进

- **ModelResolver** 服务先统一用途路由，再考虑独立 Provider 插件注册；用现有模型配置验证扩展点。
- **WorkspaceFile / Operation / Artifact** 先接通文件修改和交付，再让 ComfyUI、文档转换与维护工具采用共同身份和查询语义；保留业务各自的持久状态。
- **SourceRef / StudyRecord / ViewAction** 支撑课件学习；视图不做权威数据，原件缺失有明确状态。
- **Trigger / ContextSource** 用现有关怀与记忆逐个验证，复用时间/额度/作用域；不引入多套后台调度。
- API 路由按 chat、identity、models、learning、operations、channels 等领域拆装配，处理业务时逐步缩小对整个 Server 的依赖。

DSH、dsh-Go、Aurabot、AstrBot、EduWork 继续以仓库已固定源码与归属记录为参考；本次未刷新上游，也不对其最新功能作判断。引入具体组件时核对相应 commit 和文件许可，保留通知。沿用成熟实现优先于为了“全插件化”自行建平台。

## 6. 规划取舍与验证

近期不建设多用户 SaaS、插件市场、整库双向自动同步，也不为了架构统一重写所有存储、迁移前端框架或替换传输协议。服务器小精灵和 ComfyUI 继续服务真实任务：受限维护需要操作记录与复查，图像重启未知态需要按桥端 job ID 核实，不能重新提交猜测结果。

每个实现合批做一次关键验证：文件冲突/恢复、模型路由、来源/动作幂等、实际启动；付费模型请求只验证必要的真实链路。测试通过后才做同批构建发布，最后对同一成品核对健康。测试数据不替代真实 QQ/手机证据。纯文档规划不触发 APK 自增或生产重启。

建议下一次实施范围是基础链路三项，加上主动陪伴分类反馈和 UI 状态一致性；PDF/学习记录、Windows shell 与真实 QQ 分别沿其依赖推进。这里是能力优先级，没有工程日期、工期或强制发布批次。
