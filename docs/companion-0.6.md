# 0.6.0：连续聊天、事件接续和应用内关怀

2026-11-02，三个方向合并交付为 0.6.0，沿用 Go 标准库、原生网页与 Kotlin 包装。未引入外部 Agent 实现或新增第三方模块。QQ、微信、B站接入继续保持低优先级。

## 直接使用

Android 顶部点“更新”，安装 **chat-agent 0.6.1-debug（versionCode 6）**。网页刷新即可；服务器地址仍为 `chat://47.117.40.74:9992`，原有自动登录继续生效。2026-11-03 产品统一改名，包名、协议和存储标识保留兼容。

1. **连续聊天**：回复过程中可继续输入、发送，等待消息显示在输入框上方。450 毫秒窗口内同交流方式的消息最多合并四条处理，保留独立用户消息；已经启动的生成不会被后来的消息自动打断。普通短回复最多三个语义气泡，代码、列表和长说明保持完整。
2. **事件记忆**：侧栏点“事件记忆”，手动保存愿意下次继续聊的事情；也可在聊天中明确说“记住这件事”或“下次再聊”，模型可提出待确认候选。候选需要在面板确认才用于后续会话。支持编辑、告一段落、不主动提及、删除，以及查看聊天来源。每个角色独立保存。
3. **主动关心**：侧栏点“关怀收件箱”。默认关闭，自动生成也单独关闭。先开启角色关怀，给事件设置跟进时间并允许跟进；到期后可手动点“生成问候”。进一步开启自动生成后，页面可见时才会检查并按额度生成。可选每日问候时间，留空则只跟进获准事件。

默认每天最多一次，支持设置 1–5 次；安静时段默认 22:00–08:00，按服务器配置的用户时区解释，当前为 Asia/Shanghai。起止相同表示不设安静时段。失败、中断也占用当天生成额度，避免不确定调用被反复收费。不因用户未回复而追加催促。

这次提供的是应用内收件箱：关闭应用后没有系统推送，也不会由后台定时器持续调用模型。关闭关怀会取消尚未交付的问候；已交付、已读的收件箱历史仍保留。生成请求已经发出时，上游是否收费由模型服务决定，取消不保证退款。

## 中断与恢复

服务端先持久化消息再确认接收。客户端刷新、断网、切到后台或退出登录后，已接收任务继续执行；需要停止时使用聊天“停止”按钮。停止会保留待发送消息并暂停队列，用户可撤回等待消息，或点击“继续发送”。刷新和重连仅读取，不自动重新提交或继续队列。

提交结果不确定时保留原请求标识，提供查询和“用同一标识确认提交”；相同标识和内容不会启动第二次调用。不确定请求确认前可继续编辑下一条草稿，暂不接受新提交。服务重启将运行中的任务标为中断并暂停余下队列，不自动重试收费请求。该机制避免自动重放，不承诺上游端到端 exactly-once。

每个会话最多八条等待消息，每批最多四条、总内容不超过 64 KiB；最多四个会话并发生成。每会话保留最多 2048 个去重标识，达到上限后新建会话；只保留最近 32 条队列完整载荷，已完成聊天继续存于原 JSONL。生成进度最多每秒落盘一次，异常退出可能缺失最后约一秒的部分文本。中断文本显示明确状态，不作为完成的助手回复进入模型上下文。已执行的工具操作不因停止而撤销。

新版网页通过队列 API 提交并在活跃时约每 600 毫秒读取历史/进度；隐藏页面停止轮询。旧版 SSE 端点继续支持原有断开取消行为。

## 纠正、删除与数据

事件分为待确认、正在经历、已告一段落和不主动提及。只有获准事件进入上下文；进行中的事件优先，已结束事件按关键词相关性选择，最多五条，不是向量检索。

修改、隐藏或删除已确认事件会保存该角色现有会话的上下文起点，后续请求跳过此前聊天及旧摘要，防止旧描述覆盖纠正；原始聊天仍可查看。这也会让模型暂时失去这些会话的其他早期聊天背景。角色正在生成时需要先停止再修改，避免上下文更新与生成交错。新消息、其他长期事实、已交付关怀、导出和备份是独立数据副本；事件删除不等于全盘物理擦除。

新增数据目录：

```text
<data>/
  turns/<session>.json        # 去重标识、队列、部分生成与中断状态
  life/state.json             # 角色事件、上下文起点、关怀设置/额度/收件箱
  companion/<role>.json        # 原有陪伴偏好
  chat/<session>.jsonl       # 原有聊天日志，不修改记录格式
```

新增目录使用独占实例锁与同步后替换写入；正常关闭释放锁。异常退出留下的锁需要确认无写入进程后处理，不自动抢锁。回退上一版程序保留新增目录，但旧程序没有新功能；再次升级不会自动重放中断模型调用。
