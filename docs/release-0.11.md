## 自然聊天和记忆

仍采用系统提示词与实际工具目录，由 LLM 自行决定直接回应、读取指引或使用工具，不添加关键词路由或显式模式切换。注册工具上限增至 24；默认每轮最多 4 次工具执行、4 次模型响应和 30 秒，额外工具不会扩大执行预算。

可以自然表达更正或遗忘，例如“我早就搬去苏州啦，之前那条记录已经不对了，顺手更新一下吧”。模型先定位实际记录和版本，再决定修改；找不到或意图不明时应简短澄清。新事实、事件仍按原规则提出候选，不自动通过审核。工具不能把 pending 改成 approved。

合并限同角色、同审核状态的 2–8 条事实，一次写入保留第一条作为主记录，删除其余记录。主记录保留创建时间和会话来源，并在原 Source 字段保留最多 32 条来源引用；不复制已被替换的旧内容。普通界面显示“合并记录”，模型日常参考不重复注入整段来源 JSON。

纠正、遗忘和合并会推进该角色已有会话的上下文起点，避免旧聊天/摘要把旧事实带回来。事实与上下文位于不同文件，先写边界再改事实：极少数事实写入失败时，内容不变，但上下文起点可能已经推进。这是保守保护，不是跨文件事务。原聊天、导出和备份仍是独立副本，遗忘单条事实不代表物理擦除所有副本。

## 关怀节奏

默认关怀与自动生成仍关闭。默认最小间隔 **180 分钟**，可设 **15–1440 分钟**；每日额度仍为 **1–5 次**，默认一次。新增“暂停到”日期，安静时段、额度、间隔和暂停均由服务端在预留尝试时检查。失败和中断同样占用尝试与间隔，不自动重试。

可直接告诉助手想怎样调整，例如“最近想安静一点，到明天晚上八点再说，之后问候也至少隔四小时”。`care_preferences` 负责读取和修改当前角色设置，保留未要求改变的字段；暂停/恢复不隐式开启关闭着的计划，设置工具本身不生成收费问候。

问候生成只使用获准事件、最多三条相关已审核事实和最近三条已交付问候作为参考，按实际尝试时间排序，避免重复问法、未回复就催促或虚构共同经历。不会将事件原始来源引文或其他角色记录混入问候。

## Android 本机通知

安装 **0.11.0-debug / versionCode 8**，在“关怀收件箱”底部开启“本机通知”，并允许 Android 系统权限。默认关闭，权限只在用户明确开启时申请；拒绝后需在系统设置允许，不循环弹窗。

首次同步只建立已有问候基线，之后手机同步的新 ready 问候可通知一次。按服务器、角色和条目去重，使用时间水位及有界 ID 记录，重启不重复弹；关闭本机通知会清除本应用当前服务器的关怀通知，不修改服务端关怀计划。锁屏隐藏正文，点击通知打开应用。

**这是已同步内容的本地通知。** 网页仅可见时同步；没有后台拉取、保活、FCM 或关闭应用后的远程推送。新关怀仍需满足服务端计划、设备权限和当前同步条件。通知失败不影响收件箱内容，旧包仍可聊天和查看收件箱，但没有本机通知桥。

## 验证和升级

本次只新增三条关键集成流程：工具重复保护、知识管理、关怀节奏；另运行四项直接相关已有流程，共七项检查。没有完整矩阵。API 35 隔离模拟器通过同签名覆盖安装、鉴权桥、间隔/暂停表单、显式系统权限、首次基线、通知一次、重复不弹和关闭。

服务器隔离数据通过三轮 ecnu-max 对话：普通陪伴不改记录，杭州旧事实更新为苏州，关怀自然设置暂停与四小时间隔。实际写入状态与工具结果一致，未使用生产个人数据，也未自动重试收费请求。

安装身份、签名、公钥和登录存储继续沿用，服务端聊天/活动/候选文件保留。关怀文件新增设置与尝试时间字段，新版可读取旧文件；旧严格解码器不保证读取新版写入的关怀文件。降级前应保留新增数据副本并用升级前一致性备份恢复，不直接切回旧二进制。发布前会正常停止服务并备份生产数据，详情见[部署说明](../deploy/README.md)。

语音和第三方 IM 尚未加入；真实手机、多设备矩阵与长期运行验收仍未进行。
