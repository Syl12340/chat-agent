# 陪伴、双端 Agent、GenUI 与 IM 的第一组共用改造

日期：2026-11-15。基于 `75747a8` 的后续工作区改动，尚未发布。

本次先实现四条方向共用的来源、任务和状态基础，没有宣称四条产品路线全部完成。

## 已实现

- turns v5 为外部消息持久保存平台、机器人账号、私人/群受众、会话目标和发送者。应用消息沿用零值，不改变旧请求摘要与旧 JSON。
- 队列只合并来源、发送者、受众、模型和思考参数均相同的请求。应用、QQ、不同群或群内不同发送者不会进入同一模型轮次。
- 完成回调携带根轮次来源。QQ Official 和 OneBot 只处理匹配自己的来源与当前 mapping，且必须找到相应 Inbox；应用轮次不会因为 session 关联而建立 QQ 投递。
- 主动关怀和共同话题的目标选择跳过当前已知群会话。群 mapping 不能关联到带现有消息的私人会话，关联前还会核对两个会话没有排队消息。
- 本机执行端领取任务时必须使用匹配协议。回执绑定目标设备、协议、operation 和原任务 SHA-256；其他已配对设备或摘要不匹配的回执被拒绝。
- 本机 operation 状态和近期回执统一持久化。服务器重启会把运行中任务标为 interrupted，但允许原设备用相同任务摘要补交晚到终态；不会重新执行任务。产物元数据随回执恢复。
- 消息队列显示 QQ 来源；本机工作台使用可读的任务/状态名称，展示执行端、失败原因和产物数量。PWA cache 更新为 v37。

## 仍有的边界

以下是本组完成时的边界；其中持久 session audience 与完整 task body 已在[第二组共用改造](audience-operation-slice-2026-11-15.md)补齐。

- 群作用域仍由当前 channel mapping 参与判断，尚未成为独立、永久的 session audience 记录。真实群入口继续保持关闭。
- 本机端保存完整 receipt，但不恢复正在运行的进程或完整 task body；重启后的 late receipt 只做摘要匹配和终态结算。
- Windows 本机端仍是工作区 guard 加固定动作，不是可运行任意 shell 的 OS 沙箱。
- 本次没有实现批注前端、侧聊、完整任务 surface 或新的陪伴生成策略；这些继续使用[总规划](product-direction.md)中的契约。

- API 关键测试通过：应用轮次不建立 QQ 投递、本机设备/摘要校验、晚到回执恢复，以及已有 OneBot 私聊闭环。
