# P0 实现与兼容性报告

更新日期：2026-10-26。

此文保留 P0 阶段的运行时验证记录。P1 的 HTTP/PWA 已实现，当前交付与测试结果见 [P1 报告](p1.md)。下文“3 项测试”和后续范围均为 P0 阶段记录。

## 当前技术决策

依据新的项目约束，移除 Harness 和全部传递依赖，项目内重新实现最小运行时。外部项目仅作为设计参考，不导入、不复制源码，也不依赖外部 SDK。

`go.mod` 只有模块名和 Go 版本；不需要 `go.sum`，构建和测试均无需下载依赖。当前工具链为 `go1.26.2 windows/amd64`。

## 已实现行为

| 能力 | 实现 |
| --- | --- |
| 自定义 Provider | 标准库 `net/http`，Base URL、Key、模型 ID 由进程环境传入 |
| Chat Completions | 模型 ID 原样发送，Bearer 认证；默认 `max_tokens`，可显式选择 `max_completion_tokens` |
| SSE | 解析文本和按 index 分片的 tool_calls，完整解析后执行；必须有有效 finish reason 和 `[DONE]` |
| 工具循环 | 助手工具调用 → 按 call ID 回传 tool 结果 → 再请求最终回答 |
| 权限 | 仅允许 `get_current_time`；未知工具、非法参数和超额调用返回错误结果 |
| 预算 | 默认 4 回合、4 次实际工具调用、1024 输出 tokens/生成、30 秒整次运行 |
| 协议边界 | 单条 SSE 行最多 1 MiB、每次响应最多 4 MiB、最多 64 个待处理工具调用；截断或缺少结束标记不执行工具 |
| 取消 | HTTP 请求继承 context，Ctrl+C/超时关闭响应连接，返回取消原因 |
| 持久化 | 项目内版本化 JSONL，每批写入后文件 Sync；assistant/tool 消息作为同批记录保存 |
| 写入互斥 | 会话内互斥锁和跨进程独占创建的锁文件，Windows/Linux 共用实现 |
| 失败处理 | 写入错误保持失败状态，禁止在该实例继续追加；旧格式、截断或损坏文件拒绝加载，不自动改写 |
| 日志 | 不输出认证配置和服务错误正文，CLI 替换错误中的 API Key |

每次生成的输出预算不是整轮累计 token 预算。实际工具调用数与模型循环数单独计数。回调同步执行，调用者应及时返回。

## 最小测试范围

仍然只有 3 项本机集成测试，使用虚构凭据，走实际项目内 HTTP/SSE 实现：

1. `TestStreamingToolLoop`：工具参数分片、时间工具执行、未知工具拒绝、工具调用预算、assistant/tool ID 对应关系、最终流式回答，以及关闭后工具记录重读。
2. `TestSessionResume`：普通回答保存后重建 Session/Agent，验证历史送入下一次模型请求；Windows 不允许以已知错误代替成功。
3. `TestCancelStream`：流式开始后取消，验证取消原因保留、运行结束和上游 HTTP 连接关闭。

本机最终结果：

| 检查 | 结果 |
| --- | --- |
| `go list -m all`（`GOPROXY=off`） | 仅 `chat-agent`，零第三方模块 |
| `go test ./... -count=1 -v`（`GOPROXY=off`） | 3 项通过，测试包耗时 0.084 秒，不含编译；Windows 恢复无同步错误 |
| `go build -buildvcs=false -o bin/chat-probe.exe ./cmd/probe` | 成功，Windows amd64 产物 9,119,744 bytes，约 8.7 MiB |

测试需允许本地回环连接；未连接真实模型服务。没有增加测试矩阵、压力测试或独立审查任务。

## 平台与数据限制

- 旧版 Harness 验证实现已被替换，不再依赖其目录同步和写锁行为。当前测试直接验证新实现的 Windows 文件同步与正常关闭后恢复。
- 旧 Harness JSONL 没有自动迁移；加载旧文件将明确报错，保留原始文件。
- 锁文件在正常关闭时删除，异常退出后可能残留，需确认无存活写入进程后手动处理；没有自动偷锁或超时删锁。
- 文件 Sync 不等同于已经通过断电恢复验证，创建文件的目录没有额外的跨平台 Sync 保证。截断记录拒绝加载，未实现自动修复。
- 本次未实测 Linux 运行、真实模型 API、长时间运行资源占用或断电恢复；不将其标记为通过。
