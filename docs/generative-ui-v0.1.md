# chat-agent Generative UI v0.1 实施规范

2026-11-05。状态：**0.20.0 首版已实现，发布记录见 [0.20](release-0.20.md)**。包含四组件、来源校验、只读答案反馈与[电脑端网页工作台](desktop-web-plan.md)。继续使用现有持久格式和模型路由。

## 1. 目标与架构决定

在现有 Go + 原生 JavaScript + Kotlin WebView 上增加声明式互动渲染。LLM 决定何时用哪一种已实现组件，可信前端绘制，宿主控制回传与权限；普通聊天继续优先自然文字，不增加显式对话模式或每轮分类模型。

首版采用普通 assistant Content 内的 `chat-ui` JSON 代码块，组件定义随原消息保存。沿用当前 Provider、消息队列、轮询/流式文本与 transcript/turns v1/v2，不增加 render_ui 工具、独立 UI Action API、UI 数据库或 Harness 持久事件格式。展示不消耗工具调用次数。

这不等于完全不改后端：后端必须知道已实现的组件目录，校验交互来源，并把结构化答案限制为只读反馈。仅靠前端按钮白名单或系统提示词，不能宣称新增交互已获得服务端权限保护。

首版范围：

| 组件 | 能力 | 不包括 |
| --- | --- | --- |
| `quiz.single_choice` | 2–8 项单选，显式发送答案 | 自动保存画像、前端隐藏标准答案或权威评分 |
| `quiz.fill_blank` | 1–4 个短文本字段，显式发送答案 | 密码、文件、支付、任意业务表单 |
| `chart.line` | 有界采样折线；预设正弦波与本地参数滑块 | 任意函数解释器、音频采集、真实声谱或实时数据订阅 |
| `diagram.vector` | 二维坐标轴与有界矢量箭头，适应手机尺寸 | 模型提供的 SVG/HTML、电路自动布局、任意脚本 |

多选、判断、流程图、表格、通用表单、音频波形和声谱图为后续组件。LaTeX 完整排版、Mermaid、React、ECharts、Vercel SDK 和 DSH 插件不进入首版依赖。

## 2. UI Protocol v1

一个完整的顶层代码块只承载一个组件，使用整数 `schema_version: 1`，不同时接受材料中示意的 `version: "0.1" / blocks / actions` 另一套格式。规范 Schema 为 [chat-ui-v1.schema.json](schemas/chat-ui-v1.schema.json)。

````markdown
可以先用一道小题确认这个概念。

```chat-ui
{"schema_version":1,"id":"quiz-001","type":"quiz.single_choice","props":{"question":"简谐运动经过平衡位置时，哪个物理量最大？","options":[{"id":"A","label":"位移"},{"id":"B","label":"速度"},{"id":"C","label":"加速度"}]}}
```
````

共同规则：

- 只解释 assistant 最终回答中的独立 `chat-ui` 围栏，不解释 user、tool、引用、摘要、运行快照或其他代码块里的内容。解析器必须识别外层围栏，不能误把四反引号代码示例里的三反引号当成可执行声明。
- 一条 assistant 消息最多四个声明，每个 UTF-8 JSON 最多 8 KiB，合计最多 32 KiB；超限部分明确降级为代码，不把完整聊天截断或隐藏。
- ID 使用 `[A-Za-z0-9_-]{1,64}`，同一消息内不得重复。ID 是展示标识，不是跨会话身份或权限。重复 ID 对应声明均降级，不把后出现的声明静默覆盖前一个。
- 所有对象拒绝额外字段；拒绝原型相关键。标签只当文本。所有数字先检查有限性和范围，不能因 JSON.parse 接受 `1e309` 而把 Infinity 送入图形计算。
- 不支持未知版本、未知组件或混合两种图表数据源；不修猜字段，不调用模型自动修复。界面保留原 JSON、复制入口及简短失败原因。
- 运行时不下载 JSON Schema，也不引入通用 Schema 库。原生 JS 与 Go 实现本文使用的有限校验子集，共用相同正反例；JSON Schema 是交付契约而非要运行完整 Draft 解释器。

### 组件参数

单选：question 必填、最长 1024 个 Unicode 码点；options 为 2–8 项，option.id 最长 24 且唯一，label 最长 256。可有 title（80）。兼容示例中的可选 submit_label，但只接受固定值“提交答案”；动作及提示由宿主决定。

填空：question 与 title 同上，fields 为 1–4 项；每项 id 唯一、label 最长 120、placeholder 最长 128。字段为普通文本，提交时各值须为非空白且最多 128 个 Unicode 码点，不读取其他输入框、自动填充凭据或剪贴板内容。没有本地答案键；发送后由模型反馈，不能把模型评价宣传为确定性评分。

折线：source.kind 为 samples 或 sine，二选一。

- samples：最多三条 series，每条 name 最长 80，points 为有限 `{x,y}`。每条最多 256 点，**全部 series 合计最多 256 点**，绝对值不超过 1e6。曲线按提供顺序连线，不任意排序掩盖数据含义。
- sine：可信代码固定计算 `y = offset + amplitude * sin(2π * frequency * t + phase)`；不接受 formula 字符串。振幅 0–10、频率 0.1–5 Hz、相位 -π–π、时长 0.1–5 秒、偏移 -10–10，固定 256 采样点。
- sine 可指定 amplitude/frequency/phase 的本地滑块，滑动和重置只重绘，不发请求；不得因每次参数变化调用模型。控件范围和步长由可信实现固定。
- 固定标注 samples 为“模型提供的数据”、sine 为“函数演示”，不冒充实测或已联网核验的数据。轴范围退化时用固定最小跨度，避免除零。

矢量：vectors 为 1–16 项，id 唯一、label 最长 80，from/to 为有限二维点，绝对值不超过 1e6。自动适配坐标范围并保留边距，零向量仍有文字说明。通过可信 SVG 元素、固定 viewBox、内部颜色和本地 marker 绘制；不接受 SVG 源码、路径表达式、URL、外部字体、foreignObject 或事件属性。

## 3. 流式、消息归属与局部状态

0.19 的 Markdown 与历史重建缺少组件归属。0.20 接入独立围栏解析与状态控制器，保留每段原始 assistant 消息的归属：

1. 围栏未闭合时只显示“正在生成互动内容”与有界预览，不解析半份 JSON。
2. 围栏闭合后可校验并显示只读预览；只有完整最终消息已提交，且父回合 completed、无 tool_calls 时才启用动作。失败、停止或部分回答保持只读。
3. 渲染保留每段原始 assistant 消息的绝对 index 和原文，不能先把几个消息 Content 拼接后再猜组件来源。摘要、tool-call 中间文字也不得借卡片合并获得交互资格。
4. 组件 key 为 role/session/message_index/原始消息 SHA-256/block_ordinal/component_id。哈希在归一化换行或 Markdown 处理**之前**计算；用户改选项不改定义哈希。
5. State Controller 独立于 DOM，保存局部选项、填空值、波形参数、busy/uncertain/request_id。轮询重建视图时重新挂接同一状态，不丢焦点、输入值或重复绑定发送事件。未改变的组件尽量保持节点。
6. 当前会话最多保留 64 个有界组件状态；正在输入或待确认提交的组件不能静默淘汰。满额后较早组件先只读，用户明确激活时再腾挪已空闲状态。
7. 不把未提交答案放 localStorage。页面重载可能丢失未提交局部值；定义从 assistant 历史重建，已排队/已发送答案从既有 turns 和真实 user 消息恢复。首次挂载、重连、回看历史绝不发送动作。
8. 切换角色/会话、退出、删除会话或源轮次时销毁相应状态、监听和异步回调；进行中的回调再次核对 authEpoch、角色、会话、来源哈希。令牌正常续签不是新权限来源。

## 4. 用户交互回传与权限

选择、输入、拖动只更新本地；宿主“提交答案”按钮才发普通队列消息。按钮明确说明会向当前会话发送一条答案并调用模型。只有当前会话、可用登录、来源仍有效，且没有生成/整理、排队、未知提交或输入框文字/图片草稿时可发；已有草稿不覆盖、不拼接、不自动附带图片。

普通 POST `/api/sessions/{id}/turns` 的 content 承载固定结构，顶层保留 `chat_ui_response` 命名空间。Schema 见 [chat-ui-response-v1.schema.json](schemas/chat-ui-response-v1.schema.json)：

```json
{"chat_ui_response":{"schema_version":1,"component_id":"quiz-001","component_type":"quiz.single_choice","source":{"message_index":7,"sha256":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"},"answer":{"option_id":"B"}}}
```

示例哈希为占位值。source 和 HTTP 路径由宿主装配，答案只包含用户选择的 option_id 或实际填写的字段值。**不把模型题干、选项标签、自定义按钮文案或 actions 文本复制进 user 消息**，以免把参考文字升级成授权。scope 来自会话绑定，不接受 payload 自选 role/session。

0.20 已实现以下服务端约束，在入队、执行前及每次模型步骤复查，不依赖前端的“已校验”标志：

- 严格识别保留 envelope，含该保留命名空间但格式错误时返回 400，不退化成普通自由文本交给模型。
- source index 对应本会话已提交的 assistant 最终消息；SHA-256、组件 ID/type、组件 JSON、选项/字段集合均匹配，来源回合 completed。
- 来源仍在有效上下文范围，未被 reset、摘要覆盖或角色遗忘 floor 隔离。历史接口可增加只读 `ui_context_floor`，供前端禁用过期控件；服务端仍独立复查。过期/删除/变化返回 409，不自动重发或补调用模型。
- 普通回答消息和 UI response 不合并成同一轮；使用现有 turns.Begin 的 merge 判定隔离，保留原模型/思考参数固化。
- UI response 回合只暴露明确的只读工具目录，不能由一次答题改记忆、人设、活动进展、提醒或关怀设置。这个限制是显式协议处理，不是关键词意图分类。用户需要真实业务写入时，在普通聊天中提出请求并沿用原授权/审核。
- 不新增独立 ui.present 工具或 UI Action 路由，不更改 Provider。需要的宿主源校验和只读工具约束不能省略。

前端冻结本次 request_id、model、thinking 和整个 content，复用 turnUI 的未知提交确认。重复点击使用同一待确认标识，不重建 UUID。已发送答案在用户消息气泡内显示为宿主格式化摘要，原始 JSON 可展开查看；不会把响应 JSON 再当 UI 定义渲染。

已排队显示“待发送”，生成中显示“等待反馈”，不把接收成功称为已批改。撤回按原队列语义处理。重载或多端读取仅恢复已知状态，不自动补交；不同设备各自明确提交的新 request_id 仍是独立请求，不宣称跨设备 exactly-once。

## 5. 模型指引与失败回退

稳定 system 分区加入已实现的四种类型、紧凑模板、字节/数量边界和数据属性限制。何时展示由 LLM 判断；一般陪伴、短回应和简单事实不强制变成练习或图表。模型优先生成小声明和预设函数，而非填满全部数据限额；本功能不擅自提高模型输出/时间预算。组件前后必须有简短可独立理解的文字，旧客户端显示代码块时仍有可读回答。

不向模型声明还没实现的音频、LaTeX、流程图、通用 HTML 或业务按钮。声明是参考数据，不授予工具权限；模型不能通过组件请求凭据、提升权限或声称已执行保存。答题响应按结构化数据理解，只作当前题目反馈。

未知、无效或生成中断时保留普通回答及代码回退，不额外调用修复模型，不自动执行业务工具。渲染器采用固定本地模块的渐进加载；UI 模块不可用时普通 Markdown、登录、停止与消息队列仍能工作。模型不能指定模块路径、网络目标或 CSS。

服务端可在 status 中声明 `ui_protocol_version` 和功能开关；回滚关闭时不删历史，组件变为只读/代码回退。尚未做客户端能力握手时，不宣称已知所有在线客户端都能渲染；旧客户端有文字与围栏降级路径。

P0 固定本协议、来源与反馈边界；P1 完成围栏与状态层，先保证普通聊天降级；P2 完成四组件及本地滑块；P3 接入答案与服务端约束；P4 补 demo、桌面展开布局和最小验证后合并发布。前后依赖在一个实现批次内推进，不要求五轮用户确认或五次发布。

仅在有多个可并行的独立实现任务时委派，例如可信组件绘制、宿主协议/后端、电脑布局；主代理处理协议集成，不委派独立审查。

## 7. 最小验收

只保留四个关键流程，不做组件全排列或重复收费验收：

1. 正常 quiz/fill/curve/vector 与一个未闭合/未知/超限/恶意属性样例贯穿解析→校验→安全回退；证明无脚本、任意 URL 或表达式执行。
2. 轮询重建与历史刷新保留在当前页面输入的选择/参数；停止后的半份内容不激活动作，过期回调不串会话，桌面展开和收回使用同一组件实例。
3. 提交→未知连接结果→同 ID 确认→反馈；模型/思考不变、草稿不覆盖、源哈希/上下文过期拒绝、答案回合实际无法调用写工具，重新挂载零请求。
4. 用 demo 在一个桌面视口与一个手机视口检查 SVG/输入可用、深浅主题、折叠工作台及键盘可达；正弦波滑动不产生网络/模型调用。

沿用现有有意义的聊天回归，只在实现变化或失败指向相关行为时扩大检查。没有结果前不标记真实模型生成质量、真机软键盘或桌面 PWA 安装已验收。

## 8. 设计依据

借鉴 [A2UI](https://a2ui.org/) 的声明式描述与可信组件目录、[assistant-ui](https://www.assistant-ui.com/docs/tools/generative-ui) 的消息内组件与交互恢复思路。其当前文档也区分多条展示路径，因此不把“Generative UI 必须是一种工具调用”作为本项目要求。[Vercel 的工具结果映射组件](https://ai-sdk.dev/docs/ai-sdk-ui/generative-user-interfaces)仅作对照，不引入其 React/Node 链路。

本文定义本项目协议，不宣称兼容 A2UI、assistant-ui 或 DSH 插件 API；没有复制第三方组件源码。未来若实际复用源码，实施时另行固定版本并履行许可。Harness 3B/3C 完成后再评估独立 UI 事件，而不是为此提前改造存储。

## 9. 首版实现补充

后端在 UI 反馈回合关闭自动摘要，避免先消耗摘要请求并覆盖组件来源；正常聊天和显式整理维持原策略。当前来源低于有效 floor 后直接拒绝，要求重新提问。状态达到 64 个后只读显示新组件，用户可明确激活以替换空闲状态，不淘汰正在编辑、展开或待确认的组件。

本地 demo 输入“互动演示”可生成四组件，无模型调用；真实模式仍由 LLM 决定展示形式，不识别该演示词。实际检查与发布边界见发布记录。
