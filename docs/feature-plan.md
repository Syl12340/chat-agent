## 共用基础与开放条件

身份与可见范围支撑记忆和 IM；Operation/Receipt/Artifact 支撑执行、运维、文档和图像；SourceRef 与 View/Action 支撑学习、批注、侧聊和 GenUI。这些是依赖关系，不是排期。

0.7.0 的 QQ 路由、跨源合并、本机回执和四步 Harness 存在具体缺口。2026-11-15 后续工作区已经完成来源/受众隔离、持久群作用域、完整本机任务归属、可恢复文件入口，并将普通 turn 改为[持续 Harness loop](continuous-harness-loop-2026-11-15.md)。2026-11-16 的 0.7.16 又加入[AstrBot transport-only 网关与 Aurabot 式仿生节奏](astrbot-im-bridge.md)：连发等待采用 debounce + 最大等待，多气泡在保留结构化内容原子性的前提下最多拆三段；AstrBot 只负责已验签的收发，CA 继续唯一持有模型、记忆、工具和 Harness。真实 IM 账号、媒体通道和群聊仍未启用；本机自由 shell、长任务观察和更完整 GenUI 继续按总规划推进。见[第一组记录](foundation-slice-2026-11-15.md)与[第二组记录](audience-operation-slice-2026-11-15.md)。

0.7.17 是新的运行基线，不再从 AstrBot 网关、持续 Harness loop、多气泡表达、异步本机任务或课件 SourceRef 重新做起：

| 主线 | 已成立的基线 | 下一纵切 | 完成标准 |
| --- | --- | --- | --- |
| 仿生聊天与主动陪伴 | 连发 debounce + 最大等待、普通短答最多三气泡、结构内容不拆；0.7.17 增加可自然保存的单条/多气泡节奏偏好，网页和 AstrBot 共用 | 用实际聊天反馈继续调整“何时只回一句、何时继续接话”；把主动消息的动机、近期事件和用户反馈纳入同一上下文，不增加显式模式按钮或每轮分类请求 | 日常闲聊不为凑气泡强拆；连续输入不会抢答或无限等；明确节奏偏好跨会话生效；主动消息有来源、可沉默、可停止 |
| QQ 等 IM 联动 | 三个入口共享 CA 核心；0.7.17 增加网关状态计数、身份解绑和解绑后的未结算私聊止损 | **完成真实 AstrBot + aiocqhttp 的 owner 私聊文本闭环**：安装插件、配置密钥、一次性绑定、重启/掉线/unknown/解绑检查；随后才扩展图片和文件 | 一条 QQ 消息只产生一个 CA turn 和一组可追踪投递；应用消息不串发；解绑立即拒绝且不再领取待投递回复；生产仍默认禁群 |
| DSH Harness 与双端 Agent | 持续 loop、operation/receipt/artifact、服务器受限自由 shell、本机读写/文件回传均已有；0.7.17 增加 `local_job_start/status` 异步任务 | 增加执行端动作发现、任务取消后的端侧确认和更长保留期；客户端自由 shell 必须等可强制沙箱，不能复用当前仅工作区路径守卫冒充 OS 隔离 | 重启后仍能查询已领取任务与产物；不确定提交先查询；没有隔离后端时明确拒绝高风险执行 |

### 当前执行边界

- 真实 QQ 私聊是下一项外部验收，但需要 AstrBot/aiocqhttp 实例和账号登录；条件未具备时可以继续完善状态页、媒体契约和失败恢复，不能宣称渠道已可用。
- 群聊、主动向群发送、微信/B站写操作不随私聊自动开放。群聊必须单独验证历史、摘要、附件、工具和主动触发均不能越过私人边界。
- Telegram、飞书、企微继续暂缓；不同时扩张多个平台适配器。
- 仿生质量优先依赖现有模型和实际反馈，不新增“判断聊天模式”的前置模型调用，也不把 Aurabot/AstrBot 的第二套 Agent Loop 搬进 CA。
- 双端 Agent 与服务器小精灵共用 operation/receipt/artifact 和授权，不再各造一套任务协议；服务器维护从只读诊断开始，写操作必须提案、批准、复查、可恢复。
- GenUI 只运行声明式可信组件；任意 HTML/JS 作为隔离产物，不在登录应用域直接执行。

每个完成的纵切默认执行一次完整交付：更新规划和发布记录、最小关键测试、提交并推送、备份后部署服务器、发布同版本 APK、核对健康与校验和。为降低打包频率，一个纵切只合并发布一次；外部账号凭据、交互登录或更高权限尚未具备时，代码以默认关闭状态发布，并把真实环境验收缺口写入记录，而不是把部署另拆一轮。

## 产品主线（历史描述）

优先在现有 Android 和网页中做好同一个陪伴角色：听懂当下需要、自然接话、记得获准保留的事情、延续共同经历，并在用户愿意时主动关心。

功能取舍以“是否让下一次交流更贴近这个人”为依据。互动呈现、桌面入口、参数记忆、富文本、持久恢复和主动搭话的会话上下文已交付；下一步按需要实现持久界面更新。搜索、提醒、共同活动、语音和互动组件服务于交流本身。

0.24 不增加真实模型验收或 Android 改动。迁移只在服务停止后由 `-migrate-runtime` 执行；普通启动不会自动转换旧数据，也不会自动恢复付费模型请求或 unknown 工具。

## 持续遵守的工程约束

- 保留 Go 主服务、原生 JavaScript 页面和 Kotlin 包装；Go 标准库优先，有明确产品依据才增加依赖。
- 可克隆开源参考仓库。优先复用许可证允许的成熟 DSH 源码及组件，按 `AGENTS.md` 记录来源、版本、许可与本地改动，由 CA 核心统一授权与结算。
- 由提示词与实际工具目录驱动 LLM 选择；程序负责授权、角色隔离、版本冲突、预算和执行边界。
- 新长期事实仍走候选审核；纠正与遗忘不宣传为所有数据副本物理擦除。
- 快速小步交付，只保留关键行为的最小测试、相关回归和少量实际对话，不做完整矩阵、重复收费验收或独立审查流程。
- 子代理仅用于用户明确指定或确需高并行的独立实现，不用于独立审查、第二模型复核或小任务拆分。
