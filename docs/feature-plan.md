# chat-agent 当前规划

当前发布（2026-11-04）：服务端 **0.17.0**（`20261104-topics-02`）、Android **0.17.0-debug / versionCode 14** 已发布。第三项共同话题已实现，具备持久化随机作息、有限公开网页漏斗、模型零输出选择、共享额度及运行/分享视图，默认关闭。本批八项最小回归、构建和线上只读检查通过，没有触发真实采集或模型验收。详见[发布记录](release-0.17.md)与[机制说明](topics-0.17.md)。0.16 的 Harness 阶段 1–2、概率关怀、人设审核和删除功能保留；Harness 阶段 3 仍未实施。

## 产品主线

优先在现有 Android 和网页中做好同一个陪伴角色：听懂当下需要、自然接话、记得获准保留的事情、延续共同经历，并在用户愿意时主动关心。

功能取舍以“是否让下一次交流更贴近这个人”为依据。近期重点是实际对话质量与连续性。搜索、提醒、共同活动和语音服务于这条主线。

## 当前已上线

| 方向 | 当前能力 | 仍有的边界 |
| --- | --- | --- |
| 角色与陪伴偏好 | 角色设定、表达偏好、自然语言修改明确的长期偏好；AI 可提出 PROFILE.md 候选，由用户审核后应用 | 不把当轮情绪推测自动固化为人格或长期事实 |
| 自然聊天 | 连发聚合、消息队列、分段气泡、生成中继续输入、停止与恢复 | 自然程度仍需真实使用反馈；提示词不能保证每轮表达都合适 |
| 模型自主工具运行时 | 系统提示词、实际工具目录、LLM 选择、结果回注、连续重复工具批次保护 | 没有显式对话模式切换或关键词意图门控；权限、并发和预算由程序约束 |
| 记忆与事件 | 候选审核、角色隔离、相关检索、纠正、遗忘、事实合并、旧上下文屏蔽 | 当前为有套话过滤、词频权重与词边界的词面检索，自动参考统一限量；删除一条记录不会清除原聊天、导出和备份副本 |
| 共同活动 | 睡前闲聊、轻量复盘、兴趣话题、小目标；普通聊天中创建、记录进展、暂停、恢复和结束；跨会话只读回忆保存的进展 | 保存进展需有明确意愿，不把闲聊自动变成待办或长期画像 |
| 主动关怀 | 默认关闭；获准事件跟进、每日额度、安静时段、最小间隔、暂停与应用内收件箱；自动闲聊一次性概率闸门和沉默记录 | 自动生成由应用可见时检查触发；关闭应用后没有新增问候的可靠后台触达 |
| Android 本机通知 | 用户开启后，对已同步的新关怀通知一次，首次建立基线并去重 | 没有后台拉取、保活或远程推送，不能等同于关闭应用后的主动陪伴 |
| 语音首版 | Android 系统识别进入草稿，确认后发送；点选回答由服务端合成、播放和停止 | 未保存或上传录音；识别依赖手机系统服务；无服务器 ASR、录音消息或实时通话 |
| 客户端与部署 | 加密连接、记住登录、同签名应用内更新、服务器搜索、升级前备份 | 仍为单用户、单实例和 debug 发布；已加入独立设备白名单及撤销；定时备份和恢复演练仍待做 |

0.11 的记忆纠错与关怀节奏、0.12 的语音交互保留。本批按用户要求合并实现稳定性、自然交流及相关记忆接续；真机验收仍是明确缺口。

## 本批三个方向的交付状态

用户已要求三版一起实现；统一交付说明见 [0.14.0](release-0.14.md)。

| 方向 | 工程交付 | 验收状态与边界 |

| 0.12.1 使用稳定性 | 修复手动登录/凭据恢复竞争、过期认证回调、识别退出与新旧结果竞争 | 离线认证回归已通过；用户暂时没有真机，先开发发布，真机麦克风、网络及设备生命周期待验收 |
| 0.13 自然交流与接续 | 更新陪伴策略、工具指引和摘要规则，跟随换话题、直接回应求助，区分计划与实际经历 | 隔离 ecnu-max 四轮对话已完成，无保存状态变化；自然表达质量仍需持续使用反馈 |
| 0.14 记忆与共同经历 | 统一词面排序；事实/事件/相关活动共用预算；暂停活动可只读回忆；保留纠正、遗忘和来源 | 新增两条关键 Go 流程及相关回归通过；没有向量语义、同义改写或长期访问频率记录 |

自动参考最多四条事实、三条事件、两条相关活动，连同偏好及当前关联活动共用 16 KiB JSON 预算。整条容纳，不把截断记录当完整事实。空自动查询与无关事件不以“最近”为理由填充；模型仍可主动搜索保存的记录。

## 紧接着的待办

- 根据概率关怀、人设审核和共同话题实际使用反馈修正体验；共同话题 0.17 已部署，按实际反馈改进，见[陪伴机制计划](companion-mechanism-plan.md)。概率不替代硬预算，不随机跳过明确约定的跟进。
- Harness 后续按阶段 3A 的事件格式、权威存储和删除契约开始规划；3B 持久回执、3C 恢复迁移随后推进。
- 获得真机后完成一条完整使用流程，优先修复可复现的输入、后台切换、网络恢复和更新问题。没有实际记录前不标记真机完成。
- 根据真实聊天反馈调整重复追问、工具确认话术、时间表达和话题接续，不增加模式选择或每轮分类调用。
- 用实际检索失误决定是否需要更进一步的索引/语义能力；当前不迁移数据或增加本地模型。

## 需要条件成熟再推进

| 方向 | 为什么需要单独评估 | 开始前要明确 |
| --- | --- | --- |
| 关闭应用后的主动关怀 | 当前既缺关闭应用后的问候生成调度，也缺可靠触达，单加通知按钮无法补齐 | 服务端调度与付费预算、手机推送或后台同步渠道、安静时段、去重、停用与设备权限 |
| 更完整的语音体验 | 系统识别仅返回文字，现有 TTS 是点选朗读；实时语音涉及不同链路 | 确定可用 ASR/语音服务、费用和延迟，录音保存规则、中断与权限；先做录音消息还是实时通话 |
| 设备管理（已实施，待使用反馈） | 0.15 已加入密钥指纹、一次性 challenge、短期会话、管理员白名单与撤销 | 本轮跳过显式验收；密钥丢失后需重新审批，旧维护凭据保留兼容 |
| 发布与恢复保障 | 当前有升级前备份和 debug 更新通道，长期恢复能力尚未验收 | 正式签名与升级渠道迁移方案、定时备份范围与保留周期、一次实际恢复演练 |

这些事项按实际使用需要穿插处理；没有确认接入方式前，不承诺关闭应用后可靠通知或实时通话。真机检查和长期使用记录仍是当前验收缺口。

## 低优先级与按需待办

- QQ、微信、B站等第三方 IM/社区接入，后于现有客户端的陪伴体验。
- 会话搜索、手动命名、归档、聊天导出、文件问答和资料收藏，只有确实帮助接续话题或用户明确需要时推进。已有记忆 Markdown 导出保留。
- SQLite、向量检索、embedding、重排、本地模型和前端框架迁移，仅在现有检索效果、数据规模或维护成本出现明确瓶颈时评估。

## 持续遵守的工程约束

- 保留 Go 主服务、原生 JavaScript 页面和 Kotlin 包装；Go 标准库优先，有明确产品依据才增加依赖。
- 独立实现 Go 运行时。一般外部项目只借鉴设计；DSH 按 AGENTS.md 的明确例外允许改写复用提示词和契约设计，保留来源与 MIT 许可，不嵌入其运行时、Cordis 或插件实现。原借鉴依据保留在历史归档中。
- 由提示词与实际工具目录驱动 LLM 选择；程序负责授权、角色隔离、版本冲突、预算和执行边界。
- 新长期事实仍走候选审核；纠正与遗忘不宣传为所有数据副本物理擦除。
- 快速小步交付，只保留关键行为的最小测试、相关回归和少量实际对话，不做完整矩阵、重复收费验收或独立审查流程。
- 子代理仅用于用户明确指定或确需高并行的独立实现，不用于独立审查、第二模型复核或小任务拆分。
