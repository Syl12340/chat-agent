# chat-agent 当前规划

当前发布（2026-11-05）：服务端 **0.20.0**（`20261105-ui-01`）、Android **0.20.0-debug / versionCode 17**（`android-20261105-03`）已发布。四种 Generative UI、来源校验、只读答案反馈与桌面网页工作台已交付，关键 Go/浏览器流程和线上只读检查通过。未做真实模型组件质量或真机验收，详见[发布记录](release-0.20.md)。0.19 图片/模型/思考、后台接收、陪伴机制和 Harness 3A 保留；3B/3C 未实施，本次无持久格式升级。

## 产品主线

优先在现有 Android 和网页中做好同一个陪伴角色：听懂当下需要、自然接话、记得获准保留的事情、延续共同经历，并在用户愿意时主动关心。

功能取舍以“是否让下一次交流更贴近这个人”为依据。0.20 已补齐互动呈现与桌面入口，根据新增需求，下一步按“参数记忆与体验收口 → 富文本/可视化/UI → 陪伴接续 → 持久结算 → 恢复迁移”推进。搜索、提醒、共同活动、语音和互动组件服务于交流本身。

本文后续版本均为建议排期，尚未实施或发布；本次只更新规划与状态，不触发生产配置、数据迁移、模型调用或新版部署。

## 当前已上线

| 方向 | 当前能力 | 仍有的边界 |
| --- | --- | --- |
| 角色与陪伴偏好 | 角色设定、表达偏好、自然语言修改明确的长期偏好；AI 可提出 PROFILE.md 候选，由用户审核后应用 | 不把当轮情绪推测自动固化为人格或长期事实 |
| 自然聊天 | 连发聚合、消息队列、连续回答排版、生成中继续输入、停止与恢复、复制和回到最新 | 自然程度仍需真实使用反馈；提示词不能保证每轮表达都合适 |
| 图片与模型参数 | 每条最多三张规范化 JPEG/PNG、鉴权预览、ECNU Max/Plus 与四档思考选择；参数随提交固化 | 默认关闭思考；图片发送后交给模型，无真实识图/真机验收；新格式不支持直接切旧二进制 |
| 互动与电脑网页 | 单选、短填空、曲线/正弦滑块、二维矢量，来源验证与只读反馈；标题筛选及可收回工作台 | 由模型选择声明；不执行任意代码，未提交答案不跨设备同步；浏览器沿用 SSH 隧道 |
| 模型自主工具运行时 | 系统提示词、实际工具目录、LLM 选择、结果回注、连续重复工具批次保护 | 没有显式对话模式切换或关键词意图门控；权限、并发和预算由程序约束 |
| 记忆与事件 | 候选审核、角色隔离、相关检索、纠正、遗忘、事实合并、旧上下文屏蔽 | 词面召回已具备过滤与排序；事实候选支持配置远端语义重排，失败回退本地顺序，尚无 embedding/向量索引；删除不会清除原聊天、导出和备份副本 |
| 共同活动 | 睡前闲聊、轻量复盘、兴趣话题、小目标；普通聊天中创建、记录进展、暂停、恢复和结束；跨会话只读回忆保存的进展 | 保存进展需有明确意愿，不把闲聊自动变成待办或长期画像 |
| 主动关怀 | 默认关闭；获准事件跟进、每日额度、安静时段、最小间隔、暂停与应用内收件箱；自动闲聊一次性概率闸门和沉默记录 | 应用可见时可检查；启用后台接收且租约在线时也可后台生成，不保证省电/强停下可靠触达 |
| Android 自建接收 | 显式常驻通知、设备 challenge 会话、关怀/话题/提醒长轮询、持久去重与断线补取 | 默认关闭，无开机自启或系统省电绕过；首次/重新开启建立基线，超限回应用查看，真机待机尚未验收 |
| 语音首版 | Android 系统识别进入草稿，确认后发送；点选回答由服务端合成、播放和停止 | 未保存或上传录音；识别依赖手机系统服务；无服务器 ASR、录音消息或实时通话 |
| 客户端与部署 | 加密连接、记住登录、同签名应用内更新、服务器搜索、升级前备份 | 仍为单用户、单实例和 debug 发布；已加入独立设备白名单及撤销；定时备份和恢复演练仍待做 |

历史版本的记忆纠错、关怀节奏、语音、自然交流及记忆接续继续保留；工程实现与真机/真实模型体验分别记录。

### 近期工作边界

- 0.20 已有四组件；0.21 明确新增只读数据表、柱状图、流程图及 JSON 树。Markdown/数学走普通内容渲染，声明式结构复用 chat-ui，来源和动作边界保持一致；具体 schema 随实施固定。
- 思考强度目前只在本机保存一组 model/thinking；下一步补成按模型记忆和身份隔离，跨设备同步暂未承诺。这是参数偏好，不保存模型隐藏推理。
- 公式拟用本地固定版本 KaTeX，实施时补齐许可与资源允许列表；继续独立实现 Go Agent，不引入第二套运行时。Markdown 原始 HTML 仍作为文本，数学/图表只交给可信渲染器。
- UI 参考 DSH 的工作台组织、Codex 的运行状态表达、GPT 的阅读与输入体验；由 LLM 选择工具/组件，保持自然聊天，不增加显式对话模式或每轮分类调用。
- 陪伴接续先改进现有参考与摘要，保留审核制记忆；获准跟进和明确提醒不被概率闸门随机跳过。检索根据实际误召回/漏召回调整现有词面候选、可选 rerank 与预算。
- Harness 后续存储保留原始富文本与 UI response 来源。来源失效时拒绝，不能改写旧答案绑定另一道题；runtime 事件格式与现有多模态 v2 明确区分。详见[迁移规划](dsh-harness-migration-plan.md)。

## 低优先级与按需待办

- QQ、微信、B站等第三方 IM/社区接入，后于现有客户端的陪伴体验。
- 服务端全文搜索、手动命名、归档、聊天导出、文件问答和资料收藏按需要推进；0.20 已有本地会话标题筛选，已有记忆 Markdown 导出继续保留。
- SQLite、向量检索、embedding、本地模型和前端框架迁移，仅在检索效果、数据规模或维护成本出现明确瓶颈时评估；现有可选远端重排继续保留。

## 持续遵守的工程约束

- 保留 Go 主服务、原生 JavaScript 页面和 Kotlin 包装；Go 标准库优先，有明确产品依据才增加依赖。
- 独立实现 Go 运行时。一般外部项目只借鉴设计；DSH 按 AGENTS.md 的明确例外允许改写复用提示词和契约设计，保留来源与 MIT 许可，不嵌入其运行时、Cordis 或插件实现。原借鉴依据保留在历史归档中。
- 由提示词与实际工具目录驱动 LLM 选择；程序负责授权、角色隔离、版本冲突、预算和执行边界。
- 新长期事实仍走候选审核；纠正与遗忘不宣传为所有数据副本物理擦除。
- 快速小步交付，只保留关键行为的最小测试、相关回归和少量实际对话，不做完整矩阵、重复收费验收或独立审查流程。
- 子代理仅用于用户明确指定或确需高并行的独立实现，不用于独立审查、第二模型复核或小任务拆分。
