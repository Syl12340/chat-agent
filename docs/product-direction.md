# chat-agent 产品方向与能力设计

更新：2026-11-15。以源码 `75747a8` 和已有发布证据为基线。本文定义产品方向、具体能力、架构选择、依赖和完成标准，**不安排工期、版本或发布批次**。事实依据见[项目评估](project-assessment-2026-11-15.md)；旧 M/N 编号保留在历史文档中，不再作为当前执行顺序。

规划完成后的第一组工作区改造已接通 turn 来源/受众、QQ 回复路由、群主动目标过滤、本机回执归属/持久化和任务状态 UI，见[实施记录](foundation-slice-2026-11-15.md)。这些是四条优先方向的共用地基，不代表相应方向已经全部完成或发布。

## 1. 结论与产品定位

CA 的目标是一个持续记得用户、自然交流、能学习资料并在获准环境完成实际任务的个人 Agent。Web、Android 和 IM 是同一个助手的不同入口；Linux 工作区、本机执行端、服务器管理代理和 ComfyUI 是不同执行环境。

当前已经具备主要能力的基础实现。方向应从“再加一个工具或管理页”转向三类完整体验：

- **相处**：听懂连续表达，记得允许记住的事情，主动但不打扰；在 QQ 与应用之间延续关系。
- **学习与创作**：围绕一份真实资料读懂、讲解、练习、纠错，生成能继续编辑和下载的成果。
- **完成任务**：理解目标，选择执行端，读取资料、编排命令、修改文件、交付结果；中断后说清做到哪一步。

共同基础是可信的身份与可见范围、可恢复的任务与产物、可追溯的消息与资料引用。已有能力不重复立项；每个方向以用户完成一件事为完成标准。

### 八条方向

| 方向 | 要形成的体验 | 当前真正需要推进的部分 |
| --- | --- | --- |
| A 仿生聊天与主动陪伴 | 相处自然、长期接续、有分寸 | 记忆质量、主动动机与反馈、插话边界、多模态表达 |
| B DSH Harness 与双端 Agent | 同一聊天能在服务器或电脑完成任务 | 完整任务归属、持久回执/产物、长任务、跨设备一致性 |
| C 服务器小精灵 | 看懂服务器、提出并执行受限维护 | 宿主级只读覆盖、可批准变更、执行后复查与恢复 |
| D 插件化 | 能力可以替换，用户无需管理技术细节 | 独立 Provider/Context/Trigger/Renderer 契约、生命周期与权限 |
| E EduWork 学业能力 | 从课件到理解、练习与复习成果 | 资料结构/页码、PDF/图像、来源引用、学习状态与成果 |
| F ComfyUI 与多模态产物 | 生图过程可查，完成后持续可用 | 重启后查回结果、原图/预览、资源状态和维护闭环 |
| G DSH/GPT 风格 UI 与 GenUI | 对话简洁，复杂任务在上下文中展开 | 统一任务/资料/成果视图，批注侧聊，可靠交互与适配 |
| H QQ 等 IM 与应用联动 | 身份、记忆接续，消息去向明确 | 修复来源路由与群边界，账号撤销、投递语义和媒体适配 |

## 2. 保持的架构选择

继续使用 **Go Core + 原生 Web/PWA + Kotlin Android 壳**。目前没有证据表明更换语言能解决主要缺口。PDF/Office 转换、图像推理等可以使用有明确用途的成熟独立组件；依赖选型按能力和维护成本决定，不再声称 Go 零第三方模块。

```text
Web / Android / QQ及其他适配器
                │ 身份、输入来源、订阅与呈现
                ▼
CA Go Core
  会话与队列 · 模型循环 · 上下文 · 权限/预算 · 任务与业务结算
                │
  插件：工具 / 上下文 / Provider / 触发 / 呈现 / 设置
                │
  Linux工作区   本机执行端   特权维护代理   图像/文档服务
                │
       统一任务、资料来源和产物引用
```

图中独立扩展点和统一数据契约是目标结构，不能据此认为当前全部已实现。核心继续拥有身份、权限、会话与业务一致性；插件和外部执行端不能自行建立另一套用户身份或未经协调的 Agent Loop。

DSH 源码是优先复用来源。先定位上游实现，再决定直接使用、移植到 Go，或作为独立组件接入。不能仅因语言不同就判定“无法复用”，也不能因为使用同名接口就声称与 DSH 插件兼容。

### 五个共用契约

这些是应逐步统一的业务概念，不要求推倒现有 runtime 格式。字段落入存储前须定义兼容读取、作用域补全与迁移失败行为。

产品仍以单用户 owner 为基线。引入 Principal/Scope 是为了区分同一用户的设备、私人渠道与群空间，不等于建设多租户平台；同样，课程和工作区组织应从实际资料与任务自然形成，避免增加维护负担。

| 契约 | 应表达的事实 | 支撑的方向 |
| --- | --- | --- |
| 身份与可见范围 | 用户 Principal、设备、外部账号、助手、会话受众、授权版本、撤销状态 | 陪伴、IM、学习、执行 |
| 有来源的消息/轮次 | 稳定 ID、发送者、入口、受众、原始事件、父消息/引用、允许回复的去向 | 连发合并、插话、跨端联动、批注 |
| Operation 与 Receipt | 操作 ID、所属轮次/用户/执行端/工作区、参数摘要、授权引用、期限、状态和业务结果 | 双端 Agent、运维、图像、文档 |
| Source 与 Artifact | 来源 ID/修订/定位、文件类型/大小/hash、所有权、预览与原件、保留及下载范围 | 学业、文件回传、GenUI |
| View 与 Action | 视图 ID/修订、来源、组件能力、动作输入、权限和幂等键、本地状态与业务状态 | 工具卡、测验、表单、成果工作台 |

具体约束：

- **共享身份不等于共享全部历史**。私人和群聊作用域不能通过当前渠道开关临时推断。
- **同一会话不等于同一回复受众**。连发合并、插话和出站路由都校验来源、发送者和权限集合。
- **成功必须来自可查询的结果**。断线、超时、取消请求和进程重启不等于业务失败或回滚。
- **文件可访问不等于可对外发送**。预览、模型读取、应用下载和发送到 IM 分别授权。
- **本地交互不必请求模型**。复制、折叠、选项切换和已知规则评分本地完成；业务写入由宿主处理。
- 旧记录缺少来源时保守处理：可保留私有阅读，不能猜成公共记录、补造投递成功或自动重新执行。

## 3. A：仿生聊天与主动陪伴

已有连发合并、队列、语义气泡、表达偏好、候选记忆、共同活动、主动调度和反馈。下一步关注“是否接得住”，而不是继续增加陪伴入口。

### A1 对话节奏与表达

- 连发在有界窗口内聚合，保留各条输入身份；长消息、代码、公式、列表不为模仿聊天而硬拆气泡。
- 运行中补充区分可用于当前任务的补充、纠正、换题和取消。同一来源/发送者/权限下才考虑 steer；否则进入明确的新轮次。
- 用户换题后自然转向；未完成任务保留真实状态，不把旧任务反复塞回回答。
- 简短闲聊可以直接答，复杂请求才展开工具。避免固定开场白、每轮反问、机械复述情绪和把闲聊变成计划。
- 气泡和语音是表达投影，权威消息仍可完整引用、重放、复制和删除。

### A2 记忆与持续关系

将上下文按用途区分：近期对话、明确表达偏好、待审核事实、已确认事实、共同经历/活动、短期线索。每项都有来源、可见范围、有效时间和纠正关系。

- 近期上下文用于接话，长期事实用于持续认识用户；不把所有历史摘要当作事实库。
- AI 可以提议记忆和人格变化；明确偏好可依现有授权更新，新长期画像继续候选审核。
- 记忆写入尽量通过自然对话完成。审核卡出现在相关消息旁；设置中保留查询、纠正、遗忘和导出，不恢复繁杂的侧栏管理页。
- 检索先处理过滤、来源、时间与同义表达问题；有真实漏召回样本再采用语义索引或重排，不以向量库存在作为完成标准。
- 纠正/遗忘同时影响后续摘要与召回；清楚区分不再使用、当前记录删除和备份保留。

### A3 主动陪伴质量

保留本地概率闸门、静默时段、每日额度和单次投递，增加可解释的触发动机：已获准跟进的事件、共同活动续接、真实新资料、轻量问候。

- 明确承诺和提醒按已约定规则执行，不被随机跳过；自发问候允许沉默。
- 区分本地未触发、模型选择沉默、生成失败、已生成待投递、投递不确定、确认送达。模型选择沉默仍可能消耗 token。
- 反馈“刚好／少一点”先约束对应主题与频率，再影响表达；不能把一次未回复推断为负面情绪或关系恶化。
- 目标会话和投递端由可见范围、用户偏好和可用性确定，不能只选同角色最近会话；一次主动内容只选一个外部目的地。
- 允许短期兴趣与表达状态，但不伪装监视、真实线下经历或要求用户维持关系。
- 多模态按需求提供：分享真实可核对的图片/资料，必要时朗读或生图；不为“像人”制造固定推理开销。

**完成标准**：连发不漏答，纠正后不继续引用错误事实，换题不被拉回；用户回复主动消息时能接续；没有新意时安静；在应用和已绑定私聊中能记得获准事实，群聊不能借此读取私人信息。

## 4. B：DSH Harness 与双端 Agent

已有 Go 工具循环、逐步上下文、准入/审批、run 记录、Linux shell 与本机文件/固定动作。缺口集中在任务身份和长任务管理，不是“再加一个 exec 工具”。

### B1 Harness 深化

- 保持模型根据实际工具目录规划步骤；宿主负责权限、超时、预算、冲突和终态。
- 普通 turn 默认持续执行 model → tool → model step，直到模型完成、用户停止或总时限结束；步数/工具数只作为可选部署硬上限，不再默认四步强制收尾。
- 借鉴 DSH 的**结构化真实结果、给模型的摘要、给用户的视图**三者分离：原始结果可追溯，摘要有预算，UI 不靠反解析日志。
- 工具状态和本轮输出预算分开。用户要求不设人为回复 token 上限时，Provider 支持则不传硬编码上限；服务商上限仍客观存在。工具摘要、执行时长和文件体积仍需各自预算。
- reasoning 只显示服务商实际返回的字段，实时与历史一致；缺失时明确缺失，不伪造内部思考。
- 长工具可返回 operation 引用并继续观察；工具执行事实、业务提交和消息发布分别结算。
- 只读工具可在声明并验证并行安全后并行；写操作按资源/作用域协调。运行中插话不改变已批准操作的参数与受众。

### B2 统一任务协议与恢复

- 下发前持久化完整任务和参数摘要，绑定设备、工作区、用户/会话/轮次及授权版本。
- 执行端领取时验证协议与能力；回执必须匹配目标设备、操作 ID、请求摘要及允许状态迁移。未知操作不能静默落成成功。
- 状态至少区分排队、运行、等待授权、取消请求、已取消、已完成、失败、结果不确定、被重启中断。
- 重连按同一 operation 查询；可验证的未执行任务才允许重试。已经运行但回执丢失的操作不能换 ID 自动重跑。
- 任务记录、业务回执和产物元数据持久化；日志是辅助证据。写入失败必须进入可见故障状态。
- 浏览器关闭只停止观察；用户停止生成、取消任务和终止执行端任务各有明确语义。
- 长任务提供有界日志流、进度、取消和结果查询；交互式进程输入绑定同一操作和授权，按实际任务需要增加。

### B3 Linux 与本机执行端

Linux 已有非 root、Landlock、seccomp、时限与输出约束以及真实 shell。继续完善每任务 workspace、进程/内存/磁盘预算、可执行依赖和可批准的网络出口；缺少必要隔离时返回明确不可用，不降级成宿主裸执行。

本机当前是目录 guard 加固定动作，不是 OS 安全沙箱。目标是支持用户希望的命令编排：

- 用户选定工作区和执行端；常规读写可使用限定目录、动作、有效期的授权租约，减少重复确认。
- 固定动作继续服务常见任务；需要自由 shell 时增加可声明、可验证的 OS 隔离执行环境，或明确由用户授权的受限工作环境。
- 命令字符串允许模型编排，但授权绑定实际命令、工作目录、网络/资源范围；不能把“允许某个工具名”视为任意命令许可。
- Windows 可按任务采用适合的隔离后端；选型前验证当前系统能力，不预设 Docker/WSL 已安装。Android 壳不自动变为 shell 执行端。
- 同机多目录、多设备和离线状态由统一 endpoint/workspace 引用表达；模型不能自行指定未知主机或绝对宿主路径。

### B4 文件交付

读取文件、执行产物、发送文件使用不同权限。模型请求分享后创建带操作归属的产物，验证真实内容、大小和 hash，交给鉴权下载接口；不暴露任意服务器路径。

支持图片、文本、代码、PDF/Office 和其他允许的附件类型；不可预览的文件仍可鉴权下载。产物在重启、回执缓存淘汰和本机离线后仍有明确状态。包含凭据的生产文件不因为“LLM 可以发各类文件”就自动进入共享范围。

**完成标准**：从手机发起任务，电脑/服务器执行并交付文件；中断后可查看确切进度和结果，不重复写入；另一设备无法伪造回执；文件经过重启仍可在保留期内下载。

## 5. C：服务器小精灵

“准 root 级”理解为可覆盖宿主系统的观察与受控管理范围，不把 root shell 直接交给聊天模型。已有只读服务/日志/发布工具和固定维护动作，目标是可解释、可批准、可恢复的系统维护。

| 能力层 | 具体范围 | 结果与边界 |
| --- | --- | --- |
| 宿主观察 | 系统负载、内存、磁盘/inode、进程摘要、服务状态、指定端口、指定日志、版本/备份 | 输出有限、脱敏且注明时间；配置资源目录，避免模型任意枚举秘密 |
| 诊断提案 | 对齐指标、近期日志与变更，说明证据、假设和建议 | 不把模型猜测写成故障结论；正常状态不反复调模型 |
| 固定维护 | 白名单服务重启、固定备份、指定缓存/旧产物清理、部署状态复查 | 预授权范围或一次性审批；频率限制、持久回执、事后验证 |
| 变更执行 | 配置修改、更新/回退、扩展受管服务 | 展示目标、diff、影响、恢复方案；批准绑定内容摘要，变化后重新确认 |
| 主动巡检 | 本地规则采样与阈值、重复抑制、低频健康报告 | 有新异常才解释；主动消息不同时取得修复权限 |

特权通过独立 helper/broker 授予：具体资源、具体动作、独立记录。任务沙箱与维护代理分离。管理 CA 自身重启时，由服务外的执行者确认终态，避免“请求连接断了”导致无限重启。

SSH、防火墙、用户/凭据、其他项目等更广管理可以作为明确请求后的资源扩展；每类单独定义权限与恢复方式，不默认继承开发者部署用的 root SSH 权限。

**完成标准**：能回答“哪里异常、依据是什么、拟改什么”，批准后执行并复查；失败保留现场与恢复入口。恢复备份前明确新数据损失范围，回退命令本身不等于恢复已验证。

## 6. D：插件化与可组合能力

已有 Manifest/Catalog、授权、启停、Tool/Service 与工具附属提示。把更多函数搬目录不等于完成插件化；需要用真实业务证明其他扩展点。

| 扩展点 | 契约重点 | 适合验证契约的能力 |
| --- | --- | --- |
| Tools | 输入/真实输出 schema、摘要、权限、幂等/回执、执行端与视图 | 现有工作区、运维、搜索、学习 |
| ContextSources | 来源/范围/预算、读取副作用为零、优先级、不可用回退 | 记忆、活动、课件片段；避免各自往 system prompt 拼字符串 |
| PromptSections | 稳定规则与动态引用分离，只描述实际可用能力 | clock、角色、学习引导；不能注入授权 |
| Providers | 能力发现、模型列表、reasoning/视觉/工具支持、错误与用量规范化 | 现有服务端模型配置；凭据继续由宿主管理 |
| Triggers | 可信来源、唤醒/静默/配额、持久去重、投递受众 | 主动关怀、提醒、系统巡检 |
| Renderers / Settings | 声明式 schema、宿主动作、客户端能力降级、秘密不回传 | 学习测验、任务卡、插件配置 |

生命周期覆盖安装、配置、启用、依赖可用、当前准入、运行中、停用/排空。故障显示具体原因；停用阻止新任务并明确处理旧任务，不自动删除用户数据。每个插件声明数据格式与迁移边界，不自建第二套会话、权限和恢复机制。

静态 Go 插件适合受信代码；复杂依赖可做独立服务。MCP 可作为工具连接协议，外部 Agent/ACP 类连接只有明确委托时才采用，避免嵌套模型循环、重复费用和权限透传。任意第三方代码进入主进程不被称为“插件沙箱”。

用户主要看“可用能力与需要处理的事项”，技术目录、manifest、服务依赖放设置/诊断。新增插件不自动增加侧栏入口。

**完成标准**：替换一个 Provider、启停一个触发器和一个上下文源，不修改核心会话循环；停用后不再注入工具/提示或新任务，历史消息与产物仍可读。

## 7. E：围绕课件的学业能力

目标不是把文件变成一段摘要，而是建立**资料 → 讲解 → 练习 → 反馈 → 复习/成果**的连续过程。已有文本提取、课件 list/read、聊天测验组件、文献搜索和批注后端；PDF、页级引用、侧聊和学习档案不能算已完成。

### E1 资料基础

- 保存原件与不可变版本，记录 hash、提取器版本、格式与提取状态；原件、提取文本、预览图各有独立产物。
- PPTX 保留页序、标题、正文、备注、图表/图片引用；DOCX 保留段落/标题/表格；PDF 以页为基础提取，扫描件按需 OCR。
- 数学公式、图片和图表不能仅以“提取到了文字”算理解完成；允许模型按需读取当前页图像，注明识别不确定性。
- 标准 SourceRef 指向资料 ID + 修订 + 页/段/范围；引用能打开具体原文。文件替换不能让旧答案悄悄指向新内容。
- 课程/资料集用于归档，不要求手工建立复杂知识库。上传即能用，课程和主题由模型提议、用户可纠正。
- 检索先做结构切分、词面和标题/页定位；规模或效果需要时再加语义检索。提取失败与不支持格式明确可见。

### E2 分析与讲解

围绕用户选定资料：整理结构、概念与先修知识，区分课件原意和模型补充，支持逐页、局部选段、公式推导、例题和简洁概览。

默认跟随用户问题，不强制“学习模式”。看不清图、缺页或资料没有依据时说明缺口；引用页码必须来自提取结果，不由模型猜测。允许在任务沙箱中计算/画图，但明确区分模型解释和实际执行结果。

### E3 练习、反馈与学习记录

- 题目绑定知识点与资料版本，包含题型、答案/评分规则、解析与引用。模型负责出题，宿主验证结构。
- 客观题可本地评分；主观题按明确评分维度给反馈，模型判断有争议时允许用户修正。
- 答题记录独立于展示卡和聊天文本，刷新不重复提交，跨设备能继续；一次答错不自动变成长期能力评价。
- 用户同意后保存错题、薄弱概念与复习目标；复习提醒复用现有 Trigger，不另建一套定时器。
- “讲解这道错题”“换一道同知识点题”沿用来源和上下文；答案与提示按用户操作渐进展示。

### E4 批注、侧聊与成果

- 批注从稳定消息/资料选段进入同一草稿模型；可编辑、撤销和恢复，不直接拼接不可追溯的隐藏提示。
- 侧聊固定创建时的来源快照与权限，独立上下文和费用；收起不等于停止，关闭明确停止/归档。不自动把未确认结论写回主会话。
- 产物包括学习指南、思维导图、闪卡、题集、报告、可编辑演示与表格。都关联来源、生成任务和版本；预览与下载共享 Artifact。
- 沿用会话右侧工作台展示成果，手机使用详情页/抽屉；不为每个成果类型增加永久菜单。
- 文献能力应分别覆盖来源检索、书目去重、来源 BibTeX 和可获取全文；当前关键词/DOI 提取不能代替完整学术引用工具。

### E5 EduWork 复用选择

本次核对固定到 `6101c32eee24e9ad556a75b9daed56c6437f5c38`。Knowledge Studio 已拆出 artifact-services，可独立于机构账号使用；具体源码依赖仍需在引入前检查，不能把可独立安装理解成可直接装进 Go 宿主。

| 上游能力 | 拟采用部分 | CA 适配位置 |
| --- | --- | --- |
| Knowledge Studio | 资料/成果/引用模型、测验闪卡、成果组织 | 学习领域服务与工作台 |
| artifact-services | 文档转换、预览、Office/媒体处理的成熟组件 | 有版本的文档执行服务，CA 统一任务与产物归属 |
| dsh-annotation | 选段快照、来源身份、草稿修改/版本与发送协议 | 现有批注存储加可用前端，不复制第二套草稿 |
| dsh-side-chat | seed 快照、独立会话、关闭/归档语义 | 核心派生会话与右侧面板，不迁移其 DOM/宿主补丁 |

**完成标准**：导入一份含公式/图片的真实课件，准确定位某页讲解，完成带解析的练习，保存并复习错题，导出带来源的成果；重开后仍能找到原页和作答记录。

## 8. F：ComfyUI 与多模态成果

已有 job ID、查询、定向取消、profile 白名单、生成图片导入与参数/hash 记录。后续目标是跨断线与重启的可恢复服务。

- 区分桥连接、ComfyUI 进程、profile/模型就绪、GPU/内存资源、队列与运行状态；健康检查不启动推理或下载模型。
- 服务端操作 ID、桥任务 ID、ComfyUI prompt ID 建立可查关系；保存提交摘要与模型/profile/workflow 版本。
- 提交回执丢失先查原操作；无法核实时明确 unknown。已有 renderer ID 时支持重启后重新观察并导入结果，不能永远停在 unknown，也不能重新生成冒充恢复。
- 取消区分请求已发、渲染器确认停止和结果不交付；不使用会中断其他用户任务的全局取消代替定向取消。
- 原图、预览图、输入参考图与元数据分别保存，历史图片查看不依赖本机在线；支持图像编辑时继续验证输入归属和 profile 能力。
- 插件/模型/节点版本更新、显存释放、磁盘清理属于明确维护操作，不随普通聊天自行执行。
- 图像、语音与视频最终共用 Artifact/Job；语音保留系统识别进草稿和点选朗读，录音消息/实时通话按明确需求扩展。

**完成标准**：提交后页面断开仍能查到同一任务；服务重启可核对渲染结果；本机关机后已导入图片仍可用；失败说明对应环节，重试不重复花费。

## 9. G：客户端与 Generative UI

UI 已经改过。以现有精简侧栏和主题为基线，继续减少需要用户手工维护的入口，避免重新叠一套皮肤。

### G1 信息组织

- 左侧主要是新对话、会话搜索/列表和设置。
- 记忆、提醒、活动、任务、学习资料从对话中的相关卡片和输入区附件入口进入；全局管理保留在设置/搜索，避免“隐藏入口后无法找回”。
- 右侧工作台承载当前资料、任务、成果、必要的侧聊；手机转为单任务详情/底部面板，不照搬桌面窄侧栏。
- 模型与思考强度是输入参数，按现有服务器配置与偏好记忆呈现。密钥只保存在服务器，普通界面不显示原始密钥。
- 服务不可用、待授权、执行失败、结果不确定给出一个合适操作，不让用户阅读内部 JSON 才理解现状。

### G2 内容、交互与工作台统一

| 层次 | 内容 | 行为 |
| --- | --- | --- |
| 阅读层 | Markdown、LaTeX、代码、引用、图片、服务商 reasoning | 安全渲染，复制与来源跳转，历史重放一致 |
| 轻交互层 | 选项、测验、清单、表格、图表 | 零模型的本地操作；需要解释时再提交上下文 |
| 持久视图层 | 学习进度、任务面板、可更新成果卡 | View ID/revision、来源有效性、跨端同步 |
| 业务动作层 | 提交答案、应用修改、下载、授权 | 宿主验证来源、权限、修订与幂等；模型文字不能代替授权 |

- 用户输入和作答独立于模型生成视图保存；更新卡片不能覆盖未提交草稿。
- 任意生成 HTML/JS 不直接运行在登录应用域。确需交互式网页成果时，作为隔离预览产物，仅开放明确桥接能力。
- 工具卡使用简短标题、参数摘要、执行端、真实状态和产物；详细日志按需展开。
- reasoning 区与答案区分离，不显示模型未返回的推理，不将其放进通知或长期记忆。

统一明暗主题、焦点、键盘/触屏、文本缩放、表格溢出和长公式。参考 DSH 的运行/工作台、GPT 的阅读/输入、Codex 的任务状态，各取结构，不混用三套视觉规范。

**完成标准**：用户无需理解内部工具和插件就能完成上传、执行、审批、学习与查看成果；刷新后卡片和输入状态可信；手机和桌面都能顺畅使用，侧栏不随功能数量增长。

## 10. H：QQ 等 IM、共享记忆与联动

QQ Official、OneBot 与 AstrBot transport-only 已接入同一个 CA 核心，来源/受众路由、持久群作用域和主动目标边界已完成首轮修正；三个生产入口仍关闭，尚无真实账号闭环证据。下一步是验证 owner 私聊文本全链路，再在同一身份和受众契约上增加媒体。接入目标始终是同一个助手的不同入口，不是把私人会话广播到所有渠道。

### H1 身份与会话

- 外部账号通过已登录应用生成的短期一次性绑定流程归属 owner，后续无感认证；绑定/解绑/撤销/重新绑定完整可见。
- 设备指纹指密钥身份及 challenge 签名，不依赖可复制的硬件字符串，也不把平台昵称当身份证明。
- 已绑定私聊可以使用相同 owner 的获准记忆；默认各保留自己的对话历史。明确关联只改变后续接续，不能改变旧消息的受众。
- 群空间以平台/机器人账号/群身份持久标记，具有独立历史、摘要、资料和记忆范围；停用渠道不把群历史变成私人历史或相反。
- 群不能关联到含私人历史的会话。群里的 owner 身份也不自动获得群可见的私人文件/服务器能力。

### H2 入站、执行与出站

- Adapter 做验签/身份归一、去重、媒体校验和能力描述，进入同一 Go 队列与 Harness。
- 每条输入保存来源和可回复目标；合并与 steer 以同来源/发送者/受众/授权为条件，不能只比较 model/thinking。
- 出站依据本轮显式来源与 delivery intent，而不是“这个 session 绑定过 QQ”；应用发起的普通消息只留应用。
- 原文生成与渠道渲染分开：长文本、引用、图片、文件和不支持的 GenUI 有清晰降级。发送外部文件按受众重新校验。
- 平台确认、失败、unknown 分别记录；请求成功不等于对方已读。发送不确定不自动重发。
- 主动消息先选择允许的会话/受众，再组装上下文；禁止把私人关怀先写入群历史、最后仅靠“不发群消息”防泄露。

### H3 适配范围

QQ 是当前明确接入对象：官方接口与 OneBot 兼容入口共用核心，但维护各自能力矩阵与准入条件。真实平台接口变化在启用时核对官方资料，不根据离线模拟断言账号一定可用。

2026-11-16 已增加 AstrBot transport-only 网关首个纵切：插件停止被接管消息的 AstrBot LLM pipeline，只把规范化输入送入 CA，并从 CA 持久 Outbox 投递回复。首版默认仅 `aiocqhttp` 文本私聊、群聊关闭；它验证了多平台网关边界，不代表任意 AstrBot 平台自动获得支持。

微信、B站等保留为可实施方向：按实际可用接口/账号条件决定独立 adapter 或外部网关；资料获取、评论互动和私聊是不同权限，不一次开放。AstrBot 可作为只做收发的独立网关，避免双模型回答。**Telegram、飞书、企微继续暂缓**。

**完成标准**：同一用户在应用与 QQ 私聊接续获准记忆；解绑即时阻止新投递；应用消息不串发；群聊不能通过历史、摘要、主动触发或附件间接读取私人资料；不确定投递可查但不重复发送。

### H4 下一纵切的实际验收

下一纵切只开放 AstrBot `aiocqhttp` owner 私聊文本，不把媒体、群聊或其他 AstrBot 平台混入同一验收：

1. 在已登录应用生成一次性绑定码，经 QQ 私聊绑定；重复使用和过期码必须失败。
2. QQ 连发进入同一来源/发送者/受众窗口，只产生一个 CA turn；模型回复按渠道 renderer 输出一至三条，不重复结算。
3. CA 或 AstrBot 任一侧重启后，已结算 delivery 可继续查询；已领取但未确认的投递进入 unknown，不自动重发。
4. 应用内普通消息不发送到 QQ；解绑或关闭桥后新消息不进入模型，旧私人历史不转移到其他身份。
5. 实际账号闭环通过后才把生产状态从“已实现、关闭”改为“已连接”；图片/文件沿用媒体仓库与 artifact 权限另做纵切。
