# chat-agent 推进目标与架构路线

更新：2026-11-10。用户确认的主方向；优先于此前“主要推进消息身份与 GenUI”的排期。本文为设计目标，不表示功能已经实施或授予运行时无限权限。dsh-Go、AstrBot 与 Aurabot 已固定到具体提交并完成源码级比较，详细结论与 Remote/Presentation/Conversation 三条协议路线见[参考项目源码调研](reference-architecture-dsh-go-astrbot-aurabot.md)。

## 1. 产品目标

把 CA 建成具有持续人格和记忆、能自然交流、能在获准环境完成任务的个人 Agent。Web/Android 共用一套成熟的聊天与工作台体验；Go 核心统一组织模型、插件和执行端。服务器受限运维、本机文件任务和 ComfyUI 通过各自能力接入同一个会话。

| 方向 | 目标体验 | 首个可交付结果 |
| --- | --- | --- |
| AstrBot / Aurabot 仿生聊天 | 自然接话、连续记忆、适度主动、文本/图片/语音一致表达 | 现有平台中的连续聊天与主动回复形成同一上下文；按语义分段而非机械逐句拆气泡 |
| DSH 式双端 Agent | 同一 Harness 使用 Linux 沙箱或客户端本地工作区完成任务 | 文件读取/搜索/修改、受限执行、取消、产物回传与执行记录 |
| 服务器小精灵 | 从聊天中了解并有限管理自己的服务器 | 只读体检闭环，随后开放白名单服务的受限维护动作 |
| 万物皆插件 | 能力、提示分区、触发、模型适配、输出呈现可组合替换 | 统一声明、宿主授权、生命周期和能力状态；逐步迁移现有业务 |
| ECNU EduWork 复用 | 把成熟的资料和工作台能力带进 CA | 优先选段批注/侧聊设计、文献检索，复用已有决策接线 |
| 本机 ComfyUI 维护 | 本机在线时可生成图片，断线/忙碌时解释清楚 | 稳定桥接、任务状态与图片产物可追踪，不重复提交 |
| DSH / GPT 风格客户端 | 统一的会话、输入、运行状态、产物预览和设置体验 | 基础 UI 改造已提交，后续补执行状态、权限与产物交互 |

IM 接入继续低优先级。借鉴 AstrBot/Aurabot 的聊天组织与模块机制可先在当前平台兑现。新交互不引入“倾听/工作/陪伴”的显式模式切换；用户在自然对话中提出需求，模型按工具目录选择能力，宿主校验执行范围。

## 2. 总体架构

```text
Web / Android：会话、输入、工作台、插件设置、设备与任务状态
                         │
CA Core：身份/角色 · 会话/队列 · Harness · 授权/预算 · 持久结算
                         │
插件目录：提示分区 / 上下文 / 工具 / 触发 / Provider / 呈现
          │               │                    │
    服务器任务沙箱    受限运维代理        已配对本地执行端
    隔离工作目录      白名单服务/路径     指定目录/产物/ComfyUI
```

产品能力通过插件组合，CA 核心统一负责身份校验、授权判定、会话一致性和结算。可以直接复用 DSH 中许可适用的代码，包括工具与执行模块、插件机制及界面组件。按接入成本选择直接引入、移植或独立组件适配。依赖 DSH 插件宿主的组件需要验证其依赖和运行契约，再接入 CA 的执行与授权边界。

### 插件契约

Manifest 逐步描述 `id/version/api_version`、依赖、能力、配置 schema、执行端要求、所需权限与副作用等级。扩展点分批增加：Tools、PromptSections、ContextSources、Triggers、Providers、Renderers、Settings；不是任意修改核心的钩子集合。

安装目录、配置启用、身份授权、本轮准入和实时可用性分别记录。宿主授予和插件停用策略已随 `ad6d671` 提交，执行端接入时继续实现设备能力与本轮范围的交集。 [插件架构](plugin-architecture.md)

静态 Go 插件先承载受信内置能力；需要 CLI/GPU/浏览器依赖的能力优先走独立执行端。新增依赖有实际需求依据即可采用，不以“纯标准库”为由自行实现薄弱的隔离层。进程内插件不声称安全沙箱；运行不可信代码须有操作系统级隔离。

禁用插件停止新任务并排空/取消已有任务，释放计时器和连接；不删除业务数据。数据所有权与迁移版本归插件声明、宿主管控；每个插件不能私建一套消息历史、授权或 LLM 工具循环。UI 首批只接受内置可信 renderer 和声明式设置，外部 JS 扩展需要独立隔离方案。

## 3. 仿生聊天与持续关系

参考用户指定的 [Aurabot](https://github.com/aureth-labs/dsh-aurabot-qq)：模块化组织人格、记忆和表达，支持连续消息节奏及主动接话。参考 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 的平台/能力扩展组织。以下是 CA 的落地设计，不意味着这些机制在上游均以相同方式实现。

- **接话节奏**：复用连发聚合、排队和取消；生成中的新消息按现有队列进入下一轮，不为模仿人类增加不透明长延迟。表达段落由模型输出结构与语义决定，已有完整记录仍是权威。
- **记忆接续**：近期对话、角色偏好、获批事实、共同活动统一选取，保留时间、来源和纠正。后台只能提出候选，不自动批准长期画像。
- **角色状态**：可增加短期、可过期的表达状态与兴趣线索，但它不是用户心理诊断或长期事实。避免仅凭关键词情绪评分驱动所有回答。
- **主动性**：复用已有关怀与话题的节奏、概率、沉默和每日额度；用户明确跟进不被随机跳过。少量真实使用问题驱动重复抑制，不为每轮新增一个分类模型。
- **多模态表达**：先统一图片、引用与点选语音的展示；生成图只在需求明确时运行，不把装饰性生图变成日常聊天固定开销。

首批验收只看几条具体行为：连发不抢答/不漏答、换题不拉回旧话题、纠正后不复述错误事实、主动消息回复能接续、无新内容时允许沉默。人格自然程度与工程正确性分别记录。

## 4. Linux 沙箱与客户端本地 Agent

### 共用执行协议

拟定宿主工具：工作区列表、文件读取/检索、补丁修改、任务执行/状态/取消、产物读取。工具名在真实实现注册后才加入提示词。会话获得获准 workspace/endpoint 的不透明引用，模型不能凭参数选择任意主机或绝对路径。

执行信封至少绑定 `operation_id`、request/session/role、设备或服务器执行端、workspace、动作和参数摘要、授权引用、期限与资源预算。回执区分 queued/running/succeeded/failed/canceled/unknown。取消不保证撤销已经写入的文件；执行后断线时先查询原 operation，不生成新 ID 自动重试。

模型选择工具，核心决定是否可派发；执行端独立复核身份、授权和目录范围。参数中的 `confirmed_by_user=true` 不能作为凭证。用户可预先授予限定工作区、动作及有效期的租约，常规操作在租约内执行，避免每条命令反复确认；越界或范围升级需要真实确认。

### 服务器任务沙箱

每任务隔离 workspace，非 root 运行，限制 CPU/内存/进程数/磁盘/时长和输出；只挂载获准资料与产物目录。生产配置、会话库、SSH/模型密钥和管理 socket 不进入沙箱。网络默认关闭，按任务需要开放受限出口。

执行机制候选为受限 systemd worker 或 rootless 容器，实施前根据服务器能力做一次小规模验证；`exec.Command + cwd` 只定位目录，不视为隔离。路径规范化、符号链接与并发访问检查需要执行端落实，不能仅靠前缀字符串比较。

允许沙箱内真实 shell/开发工具完成获准任务；生产管理操作使用下一节的独立代理。产物经大小、类型和作用域检查后发布引用，不把任意宿主路径直接返回前端。

### 客户端本地执行端

首个目标是当前 Windows 电脑：独立配对 agent 通过出站加密连接领取任务，暴露用户选择的目录和可用能力；云端不直接持有本机管理员凭据。设备可撤销，任务和授权绑定具体设备，撤销后不再领取新任务。

浏览器仅负责交互；Android Kotlin 壳继续承接 Keystore、通知、文件选择等系统能力，不默认提供任意 Android shell。网页断开与执行端离线分别显示；不能把“手机打开页面”理解为电脑执行端在线。

执行输出、文件内容与产物进入模型上下文前均视为不可信数据；保留必要摘要与哈希，敏感内容不自动作为通知正文或全局日志。

## 5. 服务器小精灵：受限运维

定位为具备 DSH 式工具规划/反馈/记录能力的 CA 运维插件。后台任务仍从用户明确启用的范围启动；同一角色可解释运维状态，但不能因人格设定获得管理员权限。

| 级别 | 初始范围 | 授权方式 |
| --- | --- | --- |
| O0 只读 | CA/search 服务状态、磁盘/内存、指定端口、有限脱敏日志、发布版本、备份清单 | 显式启用只读巡检，可用低频本地规则触发，仅异常需要解释 |
| O1 有限维护 | 固定服务重启、触发固定备份流程、核查部署结果 | 指定资源和动作的宿主授权；一次性操作回执、频率限制、结果复查 |
| O2 变更提案 | 配置修改、升级/回退、备份清理 | 先给出目标、差异、影响与恢复方案，明确批准后执行 |

运维代理以单独低权限账号运行，必要特权经固定 helper/systemd 动作授予；不接收任意 `sh -c`、sudo 命令、服务名或文件路径。只能管理配置中的白名单，默认不包括其他项目、SSH、防火墙、用户/凭据系统。恢复备份涉及后续数据丢失时必须单独说明。

Agent 请求重启自身服务时，回执先持久化，再由外部 helper 执行与复查，避免 HTTP 中断被误认为失败后反复重启。巡检发现问题先诊断；自动修复仅限用户预先批准的明确动作和次数。

首个交付是“查看 CA 状态→解释异常→建议处理”，然后再加入一次白名单重启。现有 root SSH 部署权限属于开发维护流程，不转交产品内的 Agent。

## 7. ComfyUI 维护作为持续能力

沿现有 imagebridge / imgctl 与 profile 白名单维护，不把裸 ComfyUI workflow API 交给会话模型。模型可选择已批准 profile、生成参数和现有图像输入；桥端执行最终验证。

将配置启用、桥连接、ComfyUI 健康、profile 就绪、资源阻塞和任务忙碌拆开报告。检查健康不加载模型；用户确有生图请求后才启动推理。当前同步调用逐步补齐持久 job ID、查询、取消及单任务并发控制；提交结果不确定先查作业，不再次提交。

执行端记录原始产物 MIME/尺寸/seed/profile/hash，导入 CA 媒体库后的引用单独记录，避免规范化缩放被误说成原图。下载与预览要求鉴权；本机关机/隧道断开时图片历史仍能查看。

自动重连只恢复桥链路，不自动重放生成任务。不自动下载/升级模型或自定义节点；这类维护按用户明确任务执行。长期维护清单包括配置、桥版本、依赖版本、空间与任务产物保留规则，任何清理先定义目录与可恢复性。

## 9. 实施批次与依赖

原 0.30–0.32 为上一版技术排期，改为下面的里程碑；实际版本按部署基线顺延。一个批次允许 UI 与插件等多个独立任务交付，但持久格式迁移独立留出恢复步骤。

| 批次 | 交付 | 前置 / 最小验证 |
| --- | --- | --- |
| M0 基线收口 | 已提交能力与发布证据核对、授权来源修正、ComfyUI 健康口径 | 现有会话可继续使用、能力失败可解释、两端实际版本可追溯 |
| M1 陪伴与插件框架 | Carrier seam 与连接状态、聊天接续与表达改进、首批能力入目录、现有 UI 接入插件状态、小精灵 O0 | 两种 carrier 行为一致；插件启停后聊天可用；执行检查授权；巡检输出脱敏 |
| M2 双端执行 | generation/resync、Linux 沙箱、Windows 本地 agent、配对/工作区授权、任务回执和有类型产物；ComfyUI 作业查询 | 一条隔离文件任务；重连不重复终态；取消和断线不重做；越界访问拒绝 |
| M3 身份与成果 | message ID 显式迁移、持久 surface、选段批注/侧聊、文献插件 | 删除不误绑定；刷新重建；旧组件兼容；批注来源可核查 |
| M4 受限管理与组合能力 | 小精灵 O1/O2、一个业务动作回执闭环；逐步迁移 memory/activity/companion 等插件 | 双击/断线不重复操作；管理范围不可扩大；失败可核对/恢复 |

ComfyUI、仿生表达与 UI 是贯穿各批次的持续方向，不只在最后验收一次。“万物皆插件”按真实业务逐步迁移，不要求先抽空核心才能交付用户功能。若出现明确使用痛点，可在依赖满足时调整次序。

快速开发：只测本次边界与核心闭环，复用既有测试；无必要不跑完整矩阵，不安排独立审查子代理。发布仍按 AGENTS.md 同时处理服务端与 APK、完整数据/配置备份、校验和及回退命令；规划更新本身不触发部署、服务器授权扩张或插件安装。
